## C1-1 共通コアと実行先の構成（Windows x64、完了）

tque ID83（子タスク89・90・91）を完了した。Windows x64の英語・日本語を対象に、言語ごとに`darkdungeon-core.lib`を生成し、既存Qt実行先と追加のagent実行先へ同じライブラリをリンクする構成へ移行した。C1全体（ID71）は作業中で、次のC1-2（ID84）が開始できる状態である。

- ゲームのC/C++コアは`DARKDUNGEON_APP`でコンパイルする。`QT_GRAPHICS`はQtの表示コードだけへ渡す。
- ウィンドウポートの登録表と起動処理は共通ライブラリの外へ分ける。`windows.c`の登録以外の共通処理はライブラリ内へ置く。起動処理・登録表のオブジェクトも両実行先のリンク前後でハッシュを照合する。ポート名・説明は実行先から取得する。
- タイル・フォント・コンパクト表示の設定値は素のCデータとしてコアが所有し、Qt側も同じ値を使う。
- agentのリンク対象はQt Core・Network。QApplicationやQt Widgetsで画面を隠す方法を使わない。
- コアから`WIN32CON`とTTYの表示処理を外す。Qtのヘッダー検索先もコアのコンパイル指定へ含めない。ゲーム部分とWindows共通処理はオブジェクト一覧で区別する。
- `--self-check <出力ファイル>`で、コアと実際の表示コードそれぞれで求めた`glyph_map`・`glyph_info`・`window_procs`・状態・主人公・品物・敵の構造、列挙値、文字バッファを18項目で比較し、両方の値を出力する。通常起動の冒頭でも同じ検査を行う。静的なglyph／tile対応表のチェックサムも出力する。ゲームの初期化、乱数、プロファイル、セーブは扱わない。
- ビルドのコンパイル指定、共通オブジェクト一覧、ライブラリ／実行先のハッシュ、両実行先のリンクMAP、agentのDLL依存を検証用の出力先へ記録する。

agentの通常起動は、C1-2の専用プロファイル・排他・認証・開始ゲートが実装されるまで`agent_startup_not_implemented`で終了する。入力・表示の未接続境界もエラーにし、自動応答で通常ゲームを進めない。**この段階のagentはプレイ用ではない。**

ビルドと診断の手順:

```powershell
.\scripts\build-agent-core.ps1 -Language all -OutputRoot .\artifacts\c1-core-runtime
.\scripts\verify-agent-core.ps1 -ApplicationRoot .\artifacts\c1-core-runtime
```

`--self-check`はQt版にも追加した開発用の診断引数で、明示したファイルへJSONを書き込む。出力先の既存ファイルは上書きされるため、検証では新しい証拠ディレクトリを使う。ゲームを操作する引数ではない。

診断はagentをQt GUIのDLL・プラグイン・画像を置かない新しいディレクトリへコピーして実行する。Qtの設定用環境変数とQtのインストール先を含むPATHを引き継がない。`LOCALAPPDATA`・`APPDATA`・`USERPROFILE`も空の専用フォルダへ向け、診断がユーザーデータを作らないことを検査する。`iflags`のサイズだけを故意に変えた別の診断実行先が、終了4で拒否されることも試験する。この実行先は開発用の証拠フォルダにだけ置く。自己診断成功を、CLI経由の新規開始・移動・保存再開の成功とは扱わない。
