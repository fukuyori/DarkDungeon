# C0 コマンド配送・入力・表示の接続仕様

状態: C0の設計を2026-10-27に確定。通常のCコアを使い、Qtとagentウィンドウポートで共用する変更を定める。コードの接続・実行検証はC1〜C3で行う。

## 1. コマンドの範囲と構文

調査済みのWindows Qt構成では英日とも173定義あり、ID・関数・フラグが一致した。全定義は[抽出手順](../tools/agent-cli/README.md)で再生成し、以下の規則で分類する。別OS・機能構成で項目が増減した場合も、未分類の定義が残ればビルド時の対応表検査を失敗させる。

| ソース分類 | 件数 | 版1の配送 |
|---|---:|---|
| 通常 | 123 | 完全名をコアへ配送。追加の選択は型付きの質問として受け取る |
| 接頭辞 | 4 | `params.prefixes`の`reqmenu`・`fight`・`run`・`rush`。単独のゲーム行動としては配送しない |
| パラメーター付き | 1 | `toggle`。`params.option`にコアが通常変更を許す真偽設定の完全名を指定 |
| 操作環境 | 1 | `bugreport`はゲーム操作APIの対象外。外部連携を自動実行しない |
| 内部専用 | 7 | 通常APIから直接の指定を拒否 |
| 特権用 | 35 | 通常APIへ提示せず、直接の指定も拒否 |
| 未ビルド | 2 | `shell`・`suspend`をこの構成では非対応とする |

`action.params`は`command`（必須）、`count`（任意）、`prefixes`（任意、省略時空配列）、`option`（`toggle`だけで必須）とする。その他の項目は拒否する。品物・方向・文字列・位置の答えを先回りしてこの要求へ埋めず、質問が出てから応答する。

`count`はビルドの`LARGEST_INT`までの正の整数とする。今回の値は32767。省略時はコマンドを1回配送し、回数用変数は数字を入力しなかったときの0のままとする。連射数や拾得数を1へ制限せず、明示的な`count:1`とは入力列を区別する。CLI側で指定回数のコマンドを連続送信するのではなく、コアの通常の繰り返し回数として配送する。

接頭辞は順序付きの配列として最大2項目、同じものの重複は禁止。`run`と`rush`の併用、`fight`と`run`／`rush`の併用は禁止。2項目は`reqmenu`と他の1つであり、入力された順序をコアへそのまま渡す。順序が違う要求は異なる内容として扱い、APIがコアの接頭辞の順序を勝手に並べ替えない。`CMD_M_PREFIX`・`CMD_gGF_PREFIX`とコマンドの定義に基づいて対応を検査し、実際のコアの接頭辞処理も通す。キューは1要求の接頭辞と本体だけをまとめ、次の行動を先に入れない。取消・不成立で残った接頭辞が次の要求へ流れないことを検査する。

`toggle`は表示された設定の正式名で指定し、略称による複数項目の一致を起こさない。通常の設定表から取得した、実行時変更可能な真偽設定の完全名だけを受け付ける。`gc.cmd_bind->param`に相当する引数を所有する配送情報をコアへ追加し、通常の`dotoggleoption`と実行可否判定を通す。`rhack`の外から`toggle_bool_option`を直呼びしない。コマンドキュー・繰り返しへコピーする引数の寿命もコア側で管理する。

`#`・`?`による選択・一覧は`command_selection`または通常のメニュー／テキストとして扱う。コマンド選択の候補は公開124件から選び、接頭辞・内部専用・特権用を混ぜず、`#`の中で`#`自身を再選択する入口も作らない。接頭辞は`params.prefixes`だけで指定する。選択経由の`toggle`は引数がない通常のコアと同じ案内を返し、正式な引数指定は`action`で行う。`exploremode`等はコアの確認を通して変更後のモードを公開するが、その成功を通常モードの合格にしない。

`options`・`optionsfull`・`saveoptions`は専用プロファイルの設定だけを扱う。APIの通信路、保存先、認証、ウィンドウポートの選択等、起動構成の変更をゲーム内の設定へ混ぜない。`perminv`等の表示用操作は、画面なしでは通常の一覧・仮想的な表示領域として表現する。通常のコアの設定によって使えない場合のメッセージは、そのまま通常の結果として返す。

明示的な`redraw`コマンドと、QtのpaintEvent・観測の再取得は区別する。前者はコアが通常実行する画面更新であり、幻覚の表示用乱数を使う場合は操作結果として記録する。後者はスナップショットの再表示だけで、本体・表示用の乱数を追加消費しない。

## 2. コアへの配送位置

通常コマンドは、コアの入力待ちで型付きの要求を受け、`rhack`と`can_do_extcmd`を含む通常の配送へ接続する。コアのLua前処理、埋葬等の実行制約、接頭辞、繰り返し、occupationの処理を飛ばさない。

回数は通常の`parse`で解釈されたときと同じ箇所へ渡す。`gc.command_count`等を通信スレッドから書き換えない。`CMDQ_EXTCMD`を使う接続にも、パラメーターと要求の所有期間を明示して加える。既存構造が引数を持たないのに、対応済みのAPIがあると仮定しない。

コアの入力関数へ到達する前に未適用の要求の版・操作者・状態を再検査する。適用後に質問が出た場合は、その質問のスナップショットを公開し、当該要求を完了にする。質問への応答は新しい要求として受け取る。`repeat`の再実行はゲーム上の通常コマンドであり、通信の要求IDの再送とは別の意味である。

CLIの応答は、通常のウィンドウポートの戻り値と、それを使うコアの検証・記録の地点へ戻す。`CQ_REPEAT`への記録を通信層で別実装しない。数量等を複数のコア入力として消費する場合は、今の入力文脈に束縛した有限の応答デコーダーを設け、任意のキー列としてキューへ流さない。座標と決定種別など既存の戻り値だけで表せないものは、型付きの追加入力をコアで展開し、両表示先で共通のキュー型・記録の契約を追加する。

既存の繰り返しキューから回答が補われる間は、文脈の管理だけを行い、新しい質問や版を公開しない。コアが実際に外部入力を必要とするときだけ待ちを公開する。QtとCLIで同じ回数・接頭辞・数量・位置・設定引数を繰り返せることをIO-06で照合する。

## 3. 入力経路の対応表

新しいC互換の入力文脈を、各呼び出し元で開始・終了する。Qt側またはagent側の受付だけで推測しない。メニュー・More等の入れ子はスタックで扱い、各戻り経路・取消・エラーでも文脈を閉じる。

| 経路 | 公開する質問 | 応答と通常処理の接続 |
|---|---|---|
| 通常の`parse`／`readchar`／`nh_poskey` | コマンド待ち | 型付きのコマンド、回数、接頭辞。一般の質問と混ぜない |
| `getdir` | `direction` | 方角を現在の方向キー・自己・上下の意味へ変換し、通常の`movecmd`・混乱等の処理を通す。直接`u.dx`へ最終結果を書かない |
| `getobj` | `item` | invlet、質問内ID、許された素手・なし、数量、`?`／`*`に相当する通常一覧への遷移、取消。選択後の分割・所持判定等はコアを使う |
| 数量を読む`get_count`、個数指定つきの品物選択 | `number`または数量属性つき`item` | 呼び出し元の上限・数量の意味と組にして渡す。数字だけを残留キーにしない |
| `select_menu`・`message_menu` | `menu` | PICK_NONE／ONE／ANY、空選択、取消を区別し、内部`anything`を質問内のIDへ対応させる |
| 候補ありの`yn_function`と`y_n`等の経路 | `confirm` | 表示候補・既定値・取消の規則。通常許された回答へ変換し、コアの判断を通す |
| 候補なしの`yn_function` | 呼び出し元に応じた`item`・`number`・`selection`・`key`等 | 文字列を解析して型を決めない。後述の通常の単キー入力も明示的に分類する |
| `getlin`・名前や注記の入力 | `text` | 空文字と取消を区別し、バイト上限内のUTF-8をコアへ渡す |
| `getpos`と`readchar_poskey`のループ | `position` | カーソル移動、確定、取消。原位置・一時方向等の既存の後処理を保つ |
| `get_ext_cmd` | `command_selection` | 公開した完全名を通常の拡張コマンド選択へ渡す。特権・内部専用の抜け道にしない |
| `display_nhwindow`のブロック、More、物語・ヘルプ | `continue` | 続行・ページ送り・許された取消。読むだけで自動続行しない |
| `askname`・`player_selection`・セーブ選択 | `selection`／`text` | 言語別の同じ候補、職業等の許可マスク、名前、通常の復元選択を使う |
| 死亡後の質問・公開・結果 | `confirm`／`menu`／`continue` | 正常な公開結果を順に返す。最終結果の前にプロセスを終了しない |
| 呼び出し文脈がない入力待ち | `unsupported` | 診断を返して待つ。適当なキーを補わず、必須経路に残っていれば段階不合格 |

候補なしの入力には、品物以外にも、`detect.c`の調べる物のクラス、`pager.c`の調べるキー、`spell.c`の呪文、`invent.c`の分割数量や文字の割当、`role.c`の開始選択などがある。これらを一般的な確認のy/nとして処理しない。

`key`は「通常のプレイヤーにも単キーを求める」と呼び出し元で明示した入力用とする。1つの表示可能なASCIIキーまたはコアが提示した特殊キーの意味だけを質問限定で渡せる。自由なキー列・後続コマンド列を受け付けない。汎用の`nhgetch`へ来たからという理由だけで無条件に`key`へ分類することは禁止する。

## 4. 応答のデータ形

`prompt.respond.params.response`の`type`を判別項目とし、その型で未定義の項目を拒否する。

| type | データ |
|---|---|
| `direction` | `value`: 8方角またはその質問が許す`self`・`up`・`down` |
| `item` | `invlet`または`choice_id`のどちらか、任意の`quantity`。素手・なしは`special:"none"` |
| `menu` | `selections`: `choice_id`と任意の`quantity`の配列。空配列は空選択 |
| `confirm` | 表示候補の`choice_id`。コア側に公開された意味があれば`yes`・`no`等を候補の属性として示すが、文字の推測で決めない |
| `number` | `value`: 質問の範囲内の整数を表す10進文字列 |
| `text` | `value`: UTF-8の文字列。NUL・ESC・CR・LFは通常の1行入力では拒否する |
| `position` | `op`: `move_cursor`／`select`、`x`・`y`、selectでは`selection_mode`: traditional／quick／once／verbose |
| `key` | `value`: 提示した意味の単キー |
| `selection` | 提示された`choice_id` |
| `command_selection` | `command`: 公開した完全名 |
| `continue` | `operation`: `continue`／`next_page`。その質問で許すものだけを使う |
| `list` | `scope`: `suggested`／`all`。品物の通常の一覧へ遷移する |
| `default` | 追加データなし。既定値がある質問で明示的に選ぶ場合だけ |
| `cancel` | 追加データなし。取消可能な場合だけ |

itemのinvlet・choice_id・specialは同時指定できない。メニューの選択IDの重複は拒否し、PICK_ONEで2件以上を返させない。複数選択のコアへの戻し順は元のメニュー順とし、APIの配列の並べ替えで通常の選択より実行順を変えない。

`quantity`は正の整数を表す10進文字列、または`all`とする。数量と汎用数値回答の上下限・公開する個数も10進文字列で表し、JSONクライアントの53ビットの精度で丸めない。先頭の`+`・余分なゼロ・小数・指数表記は禁止し、負数はその質問が許す場合だけとする。小さい回数を指定する`action.params.count`は別であり、JSON整数のままとする。

質問が数量を許さなければ拒否する。全数を内部の`-1`等へ変換するのはコアへの接続内だけにする。上限は呼び出し元の数値型と通常提示する制約から得て、非公開の実個数を追加で教えない。

品物の強調候補だけに選択を狭めず、通常の持ち物の文字や素手の指定をコアへ渡せるようにする。コアが提示していない「除外理由」「隠れた能力に基づく成功可否」等をAPI側から追加しない。確認のESC以降の非表示候補もそのまま公開しない。数量等が通常の操作に必要なら呼び出し元でその意味を登録し、Qt側でも同じ操作の説明を提示する。

位置の範囲は`isok`に相当するマップの境界までを入力検査に使う。隠れた地形や対象の有無を使って、操作前に適否を教えない。カーソル移動は通常の`getpos`の説明と更新を通し、選択は該当するLOOK種別を使って既存の終了処理へ進む。隣接マスだけを扱う`CMDQ_DIR`や、常にtraditionalになるクリック入力だけで4種類の選択を代用しない。

## 5. 表示の接続と知識の保護

| ウィンドウポートの群 | 共通接続の責務 |
|---|---|
| init／player_selection／askname／exit | 初期化、開始待ち、選択、終了前の結果。QApplicationを二重生成しない |
| create／clear／destroy／curs | 表示領域とカーソルの寿命。破棄した領域の内容参照を失効させる |
| putstr／putmixed／raw_print／display_file／display_nhwindow | 通常の文章・書式・表示ファイルをスナップショットへ受け取り、必要なブロックを質問へ変換。生の混合glyphエスケープをそのまま外へ出さない |
| start_menu／add_menu／end_menu／select_menu／message_menu | 提示された選択肢の固定化、質問内ID、数量・選択方法、取消 |
| print_glyph／cliparound等 | 正規化した表示情報、許された背景、カーソル。クリップ外でも全実体を取得しない |
| status_init／enablefield／update／finish | 通常表示する項目と条件だけを受信。未表示・不明はnull |
| update_inventory／ctrl_nhwindow | 変更通知によるキャッシュ失効と、通常の一覧・常時表示の更新境界。観測から実体へ戻らない |
| getmsghistory／putmsghistory／doprev_message | 復元した履歴と新規メッセージの分離、通常の履歴表示 |
| nhgetch／nh_poskey／yn_function／getlin／get_ext_cmd | 第3節の文脈を確認して型付き入力を受ける |
| get_nh_event／mark_synch／wait_synch／delay_output | 通信の通知と表示だけを扱い、コアの行動を再入実行しない。画面なしで描画のための待ち時間を課さない |
| outrip／preference_update／number_pad／bell等 | 終了表示、設定・キーの意味、通知をその表示先の能力へ対応。ゲームルールの別実装を作らない |
| suspend／resume／can_suspend | 版1ではOSへのsuspendを提供せず、未対応を明示 |

すべての実在する`window_procs`の枠を実装または明示した非対応のスタブへ対応付け、未初期化の関数ポインターを残さない。コンパイル時の条件付きの枠も、各OSのビルドで照合する。

### 背景と現在／記憶の区別

現行の`display.c:get_bkglyph_and_framecolor`は現在の`levl`を参照し、ソース自身に記憶の扱いへの注意がある。このため、`print_glyph`に背景引数があることだけで、常にCLIへ公開してよいと扱わない。

共通の公開表示の生成はコアの実行コンテキスト内で行う。`newsym`、通常の地形表示、品物表示、検知、不可視の印、盲目の`feel_location`、飲み込まれ、マップ消去と視界の更新を分類する。前景はコアが選んだ表示を維持し、背景は現在表示を許した地形か、以前に公開済みの地形キャッシュだけを使う。見えなくなったマスの現在の地形・品物からキャッシュを更新しない。

知識区分の変化も、コアの表示更新・視界再計算の境界で公開用メタデータへ変換する。直接視認、記憶、検知、盲目の触知等の区別をQtとAPIで共用し、区別できないものは`unspecified`へ留める。コアの正規の魔法の地図等で公開された地形も、公開イベントを根拠に記録できる。情報を補うために再度`newsym`を呼び、幻覚を再抽選してはならない。

役割を持つ表示用の印やマスの詳細説明をQt側でも確認できるようにし、CLIだけが内部の視界配列を知る構成にはしない。マップ消去や階移動では画面の世代を変え、別の階の背景を使い回さない。公開済みの地形の記録は訪問済みの階ごとに保持し、同じ階に戻るときに対応する記録だけを使う。

`docrt`・`flush_screen`・画面消去後の全再描画でも、視界外の背景はこの記録だけから取得する。`levl[x][y].typ`から再構成しない。`iflags.use_background_glyph`等の意味に関わる表示用設定は共通の初期化で両表示先に揃え、Qtのstart hooksだけで設定する構成にしない。

### 保存・再開時の公開済み地形

ゲーム本体のセーブ形式を変えず、公開済み地形を専用プロファイルの`knowledge/`（通常起動は次段落）に補助記録として保存する。内部の階識別と公開済みの地形の意味だけを持ち、未公開の地形・品物・敵・実体の一覧を混ぜない。

通常のQt起動にも同じ生成・保存・復元規則を適用し、保存先は通常の言語別データの`knowledge/`とする。通常起動の初期化でもこの場所を明示し、CLIの有効・無効で背景の情報保護を切り替えない。通常保存先を使う実行試験は利用者の既存データでは行わず、同じ配置を再現した独立の検証用コピーで行う。

`dosave0`が状態を解放する前に公開済み地形を複製する。通常のセーブが成功する経路で、`nh_sfconvert`の後・`nh_compress`の前の確定した未圧縮セーブ内容のSHA-256を取得し、そのhash・共通コアのビルド識別子・言語・記録の版を付けて補助記録を原子的に保存する。型の違う両実行先のビルドIDではなく、共通コアのIDで結び付ける。

復元では解凍後、セーブの変換・消費・削除より前に同じ内容のhashを取得し、すべて一致する補助記録だけを使う。別のセーブや別の版の記録を、ファイル名や時刻だけで流用しない。補助記録がない・不一致・破損の場合は、視界外の未取得背景をnullに留め、現在の地形から補わない。この場合も通常の前景・ゲーム状態の復元を妨げない。

読み込んだ補助記録は復元成功まで保留し、成功後にだけ当該ゲームの表示へ適用する。復元失敗、選択のやり直し、新規開始では保留した記録と前ゲームのキャッシュを破棄する。失敗した復元の階識別を、次のゲームへ引き継がない。

補助記録の保存失敗は、ゲーム本体の保存成功と区別して通知する。旧セーブやセーブ単体のコピーには記録がない場合があり、そのときの安全な背景欠落を既知の状態として示す。検証用セーブのコピーには、対応する補助記録も含める。IO-07・IO-09で、視界外の地形変更、全再描画、階の往復、記録の有無、画面あり／なしをまたぐ保存再開を確認する。

品物はR2の同じ外見のグループへ正規化し、内部の品物型やタイル番号を出さない。外見対応の静的表はPNG制作とは分離して用意できる。未分類の表示を実体の情報から推定せず、分類できない場合は粗い表示分類と診断を返す。コアが通常見せる詳細は、通常の調査操作で取得する。画像制作は引き続きAntigravityが担当する。

## 6. 接続の全件照合と実行試験

C0では173件の定義の分類、`window_procs`の全枠、入力の主経路と公開データの接続方針を定める。実装時には生成済みのソースから入力呼び出し元を再列挙し、各箇所を既知の文脈か対象外の根拠へ結び付ける。`artifacts/cli-c0-input-call-sites-20261027.txt`は調査候補の検索結果であり、実行した入力経路の一覧ではない。

以下の検査で未分類の入力待ち、正常状態へ戻らない経路、余分な乱数・観察処理を検出する。例だけの成功を全件対応の代わりにしない。

| IO-01 起動 | 名前、職業・種族・性別・属性の全選択、物語、セーブ一覧、取消 |
| IO-02 移動と基本動作 | 8方向、扉、複数対象、容器・拾得・階段・待機、手のない姿、取消、方向入力の残留 |

C3では、単発CLIの受付応答が届かない間に別の単発CLIが次の番号を使った場合も試験する。`request_conflict`から未適用と推測して別番号で再実行せず、記録・現在の観測・最終結果から確認できる範囲を示す。結果を特定できない場合は結果不明とする。
