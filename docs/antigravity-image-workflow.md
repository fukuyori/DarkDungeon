## 制作フェーズで渡す内容

1. 制作台帳の対象と外見キー、人が読める公開外見と公開クラス、出力ファイル名、ゲーム内の表示先。[R2の外見仕様](item-appearance-contract.md)に従い、同じ外見は同じ制作依頼へまとめる。本物・偽物や隠れた効果を描き分ける情報は渡さない。
2. 最初は未承認と明記した文章の画風の方向性と、権利/公開範囲を確認した明暗別の保持地形の見本を渡す。技術メタデータ提案を解決して試作し、レモンが実物を確認した後にstyle-guideの版/SHAを記録する。以後はその承認版を参照する。旧モード画像や原作画像のコピーは添付・依頼しない。
3. [R1の画像実装仕様](rendering-asset-contract.md)に定めた原画形式、宣言した列数/コマ番号、行の順序、共通の接地点、主人公のレシピ/方向別合成順、小記号の実表示寸法、黒い輪郭と透過の条件。初回の技術メタデータ提案をロクが検査し、未解決の合成順/追加列等を依頼へ反映してから画像生成へ進む。原画のアルファは0/255とし、不透明画素に予約背景色RGB(71,108,108)を使わない。
4. 作成物だけを保存する納品先、ゲームのコード・通常のセーブ・設定を変更しない範囲。
5. 納品一覧、制作元・編集可能なデータ、使用した生成プロンプト、加工工程、ハッシュの記録。

フェーズ2は代表的な主人公・敵・アイテムで画風と納品形式を確認する。フェーズ5は5-1〜5-4に分け、全対象を作成し直す。各確認版への組み込みと実画面での確認を行い、各フェーズ・小工程の区切りでClaude Codeレビューを受ける。

フェーズ0では現行表示の記録と測定条件だけを用意し、新しいゲーム用画像は制作しない。[R7](rendering-comparison-contract.md)の代表26論理対象には小さい仲間印の派生1件を含む。Antigravityが新しい主印から派生して納品し、独立した新作や旧印の再利用と数えない。公開用の依頼下書きにはmethod/派生元も明記する。

## 受入時の扱い

- 生成直後の画像をそのまま採用せず、寸法・コマ・透過・接地点・向きの整合性を実物で検査する。
- 納品物が形式や見た目の基準を満たさない場合は、問題箇所を添えてAntigravityへ修正を依頼する。
- 既存の低品質な画像を拡大・色替えしただけの成果物は、新規制作完了としない。
- 制作に使う具体的な手段と、必要な整形・後処理は、最初の試作で記録する。受入条件を満たす実物と目視確認が揃うまで、納品可能性や品質を検証済みと報告しない。
- 実際の画像生成を依頼したときは、条件確認の会話とは分けて、依頼文・会話ID・納品先・検査結果を保存する。
