# NetHack にリアルタイムのアクションを組み合わせる試作

## 確定している方針

- Windows の C++/Qt アプリ。
- アプリ、ゲーム文章、名前、クエスト、ヘルプ、操作ガイドを英語・日本語で利用する。言語ごとにゲーム本体とセーブを分ける。
- 実際の NetHack のソースを活用する。
- リアルタイム移動、剣の抜き差し、盾、敵の行動を扱う。原作のある作品の名称・キャラクター・画像は使わない。
- ルールは両方を掛け合わせる方向。細かなルールは現段階で固定しない。
- ソースを GitHub（https://github.com/fukuyori/DarkDungeon）で公開する。全体を NetHack General Public License で配布する。

## 現在の構成

通常の冒険では NetHack の C コアと既存の C++ Qt ウィンドウポートを実行する。主人公・敵・アイテム、および壁と床以外の地形は NetHack のタイルを使用する。

画面は上から装備・ステータス、迷宮、メッセージ、ツールバーの順に配置する。メッセージは横幅いっぱいの不透明な欄とし、通常はフォントの3行分を確保する。ツールバーは下端に配置し、狭い幅では基本動作を上段、追加動作を下段に、広い幅では1段に並べる。装備欄の表示変更では上部の高さの差を迷宮で吸収し、メッセージ欄の高さを維持する。HPバーは残量と欠損分の比率でレイアウトを伸縮し、現在の幅を最小幅として固定しない。

壁と床はQPainterで描いた独自の石積み・石畳へ置き換える。壁は青みと黄みを抑えた濃い灰色、床は明るい灰色とし、壁の幅を46ピクセル、石の段を16ピクセルにし、外周は1ピクセルの灰色の輪郭にする。黒い余白とずらした影で太い帯を作らない。壁の11種類の向き・角・交差を維持し、部屋・暗い部屋・暗い通路・明るい通路は明るさを分ける。模様はマスの座標から安定した4種類を選び、48ピクセルの画像をキャッシュして現在のタイル寸法へ拡縮する。通常の冒険では表示された地形glyphだけから選ぶ。通路の周囲などに表示される石（S_stone）も全面の灰色の石積みに置き換え、実際の未探索（GLYPH_UNEXPLORED）は従来の黒を維持する。S_stoneはNetHackの設定・視界処理によって暗い場所の空白にも使われるが、描画では隠れた地形を読み分けず、受け取ったglyphだけを使う。扉・階段・水・溶岩・罠などの別の地形は元の図柄を維持する。表示更新時に見えている地形と記憶した地形を取得し、地形、キャラクター・品物の順に描画する。主人公・敵・品物・死体・像は予約背景色RGB(71,108,108)だけを透過させる。黒い輪郭と品物の模様は維持し、持ち込みのタイルは既存のアルファだけを使う。階段などの地形の図柄も石畳へ重ねる。未探索、検知だけの敵、盲目・飲み込まれた場面では現在の見えていない地形を取得せず、表示した背景だけを保持する。背景の記憶は表示ウィンドウ内だけで、マップ消去時にリセットする。通常のセーブ形式と装備欄の描画は変更しない。練習の床と通行できないマスにも同じ石の描画を使い、移動・衝突の判定は変更しない。外部の壁・床画像は追加していない。

`Practice > Realtime practice`（練習 > リアルタイム練習）は、現在の NetHack の階の地形をコピーして、独立したリアルタイムのアリーナを開く。主人公の移動、剣、方向に応じた盾、スライム・ナイト・メイジ・ドラゴンの試作行動を試せる。主人公と敵は NetHack のタイル（敵は green slime・soldier・gnomish wizard・red dragon）で描き、構えた剣は線で描く。元の冒険は停止したままで、アリーナでの位置・体力・撃破結果を元のゲームに書き戻さない。閉じるとアリーナの状態は消え、開き直すと現在の階から再作成する。これは混合ルールを検討するための試作である。

シミュレーションは 60 Hz の固定ステップ。ウィンドウの非アクティブ化では入力を解除して一時停止する。`P` で再開できる。壁、剣、飛び道具、盾の判定はシミュレーション側で行い、Qt は描画と入力を担当する。

## まだ固定していないもの

階数、宝箱の出現条件、鍵と扉、最終目的、敵とアイテムの名称対応、持ち物・魔法・空腹の採用範囲、リアルタイム状態と NetHack コアの保存・同期規則。現在の通常冒険は NetHack の規則を使い、アリーナの数値は操作感を確認するための仮設定である。

Spaceの基本動作は、利用者が確認した順序（足元の箱・袋の中身、足元の拾得、階段、隣接する閉じた扉、対象なしでは待機）をNetHackのコマンド層で選ぶ。文字入力・メニュー選択では通常のSpaceを保ち、練習では剣の操作を保つ。マップのスクロール領域にフォーカスがあってもキーをコマンドへ届け、冒険では長押しの自動反復を抑止する。扉は主人公が記憶している閉じた扉の表示から選び、複数あれば既存の方向確認を使う。箱の確認は通常のloot経路で鍵・罠・姿・手・到達可能性を検査してから、既存の中身表示へ進む。

Spaceの対象がない場合は、敵の近くでも待つという合意に従い、NetHackの強制待機経路を使う。safe_waitや他の待機コマンドの設定を変更しない。Claude Codeのレビュー後、繰り返す操作の古い応答を捨てて現在の状況を再判定し、手のない姿では未使用の方向をキューへ残さないよう修正した。再レビューでは、この範囲の追加の不具合は指摘されなかった。

自動検証では、マップへ送ったSpaceでKnightのターン数がちょうど1進むこと、長押しの自動反復を無視すること、文字入力に空白を入れられること、箱と他の品物・階段が同じマスにあるときの優先順、施錠箱の中身を漏らさないこと、箱の中身と複数箱の選択画面、拾得、上り／下りの選択、未確認の扉の除外、単一／複数扉と繰り返す操作、手のない姿でのキューの後始末を確認する。階段の実際の階移動は既存のdoup／dodownへ委譲しており、この追加テストは階の移動そのものを実行しない。通常のセーブと設定を使わず、検証用の地形・品物・設定を戻してから保存と再開を確認する。

最終のWindows Qtの証跡は `artifacts/smoke-en-windows-20261008-162734` と `artifacts/smoke-ja-windows-20261008-162746`。両言語で保存と再開、練習操作まで通ることを確認し、箱の中身の画像を確認した。短いテキスト一覧が最後の行を切っていたため、フォントの高さではなくQtが返す各行の実際の高さと枠でサイズを計算するよう修正した。ソース生成を再実行し、コマンド・拾得・ヘッダー・Qtの変更が検証済みソースと一致することを確認した。
