# R2: アイテム外見と新画像の対応仕様

作成日: 2026-10-27  
状態: R2の仕様確定済み。2026-10-27の[Claude Code再レビュー](../artifacts/claude-r2-item-appearance-followup-20261027.txt)で、完了を妨げる矛盾・漏えい経路は見つからないと判定された。画像解決処理と実行時検査の実装は後続フェーズで行う。

この文書は [表示品質仕様](rendering-parity-spec.md) と [R1の画像実装仕様](rendering-asset-contract.md) を補い、未鑑定品・未観察品の正体や外見を新しい絵から漏らさないための対応方法を定める。

## 1. 決定事項

1. アイテム画像の制作・参照単位は、ゲームが表示を許可した「外見」とする。真の種類（`otyp`）や効果の名前を、そのまま画像キーにしない。
2. 実行時はコアが外見シャッフル・汎用表示・幻覚などを処理した後の表示情報を受け取る。その `tileidx` を、ビルド時に作る外見対応表で「同じ外見のグループ」へ変換し、グループ共通の画像キーを使う。タイル番号が違っても、同じ外見なら同じ画像にする。
3. 迷宮、持ち物、装備欄、品物選択メニュー、ドラッグ画像で共通の変換を使う。同じ表示外見なら同じ原画像とし、画面ごとに真の種類へ引き直さない。
4. 鑑定しただけで効果別の絵へ差し替えず、コアの表示外見を維持する。表示名や、既存の許可された識別情報はコアの結果を使う。
5. 同じ絵を使う対象が複数あっても、制作対象から除外したことにはしない。外見ごとに画像を新規作成し、その画像に対応する全対象を制作台帳で照合する。

例えば、別のゲーム開始時に同じ色の薬へ異なる効果が割り当てられても、同じ色という外見には同じ新画像を使う。効果の種類によって瓶や装飾を変えない。まだ色を確認していない薬を、表示側が勝手に色付きの画像へ変えてはいけない。

## 2. ソースで確認した現行の仕組み

| 箇所 | 確認した内容 | 新画像への接続で守ること |
|---|---|---|
| `src/o_init.c` の `shuffle` / `shuffle_tiles` | 外見の記述番号を入れ替え、その `oc_descr_idx` に合うタイルを通常品物・積み重なり先頭の両方へ割り当てる | 現在のシャッフル後の `tileidx` を使い、未シャッフルの真の種類から画像を選ばない |
| `src/o_init.c` の `restnames` | 復元した `objects[]` から再び `shuffle_tiles` を行う | 新画像側で再抽選せず、復元後のコアの対応を使う |
| `include/display.h` の `obj_is_generic` / `obj_to_glyph` | 外見未確認の薬・一部の宝石・魔法書などは種類別の汎用表示になり、幻覚・死体・像も別の分岐で表示glyphを選ぶ | 実体の `otyp`、`corpsenm`、色などへ戻って外見を補わない |
| `src/display.c` の `map_object` | 近くで観察できた場合にコアが `observe_object` を行い、表示を更新する | 描画側で `dknown` を立てたり、観察できたと判断したりしない |
| `src/display.c` の `map_glyphinfo` | コアのglyph対応から `glyph_info.gm.tileidx` などを渡す | ウィンドウポートが受け取った表示情報を新画像の解決元にする |
| `src/qt_inventory.cpp` の `itemImage` | `obj_to_glyph(..., rn2_on_display_rng)` と `glyphmap[glyph].tileidx` を使う | 表示の標本化と画像描画を分離し、再描画のたびに別の表示を抽選しない |
| Qtの `qt_inv.cpp` / `qt_menu.cpp` | 装備欄とメニューもglyphから `map_glyphinfo` のタイルを使う | 同じ外見対応へ接続し、装備欄・メニューだけ別の絵にしない |

上表のコア側のパスは、生成するNetHackソースの中の相対パス。今回のR2作業では、これらの処理自体を変更していない。

## 3. 外見対応表と画像キー

### 3.1 静的な対応表

各ビルドで、元のタイル生成処理（`win/share/tilemap.c`）と、シャッフル前の元の英語ソースにある品物クラス・外見記述から対応表を生成し、生成物の `src/tile.c` と照合する。実行中の `glyphmap` や翻訳後の名前から静的表を作らない。タイルの物理番号と表示上の外見グループを分離する。

対応表は次を持つ。

- 元ソース・タイル対応表の版を示す識別子とハッシュ。
- タイル番号、素材元の種類、素材元の項目番号。
- 品物クラス、元の英語の外見記述、同じ外見として扱うグループのキー。そのグループに属するすべてのタイル番号と素材内番号。
- 表示上の分類（通常品物、汎用品物、死体、像、キャラクター等）と、許可される分類の別名。
- 新素材のキーとファイル、同じ画像を使う別名の対応。

通常品物の同じ外見のグループ（外見同値類）は、**品物クラスと元の英語の外見記述が同じもの**をまとめて作る。別々の記述番号でも文字列が同じなら同じグループにする。真の名前・効果・真偽・魔法の有無・材質などを区別の理由にしない。

外見記述がない項目を、一律にまとめたり真の名前へ自動的に切り替えたりしない。コアが最初から表示を許す外形の違いをソースで確認できるものは、元の英語ソースの表示上の名前を明示した外見定義として登録する。日本語への翻訳後の名前をIDへ使わない。判断できないものは分類未完了とし、R3の全件照合で解決するまで完成判定へ進まない。

画像キーは `item.appearance.<クラスキー>.<外見ID>` とする。外見IDは、`appearance-v1`、クラスキー、外見定義の種別、元の英語の外見記述の順にNUL区切りで並べた、BOMなしUTF-8データのSHA-256（小文字64桁）とする。文字の大小や空白は勝手に正規化しない。タイル番号・真の種類・効果名をIDへ入れない。各タイル番号と元の素材番号は、この共通キーへの別名として保持する。

| 同じ画像にまとめる代表例 | ソースで確認した同じ外見 |
|---|---|
| 本物・偽物のイェンダーの魔除け | アミュレットクラスの `Amulet of Yendor` |
| 幸運の石・負荷の石・試金石・火打石 | 宝石クラスの `gray` |
| 袋の複数の種類 | 道具クラスの `bag` |
| 油のランプ・魔法のランプ | 道具クラスの `lamp` |
| 角笛の複数の種類 | 道具クラスの `horn` |
| 同じ色の本物の宝石・ガラスなど | 宝石クラスの同じ外見記述。真の材質で形を分けない |

これらはシャッフルがない対象にも適用する。元タイルに違う番号が付いていることや、元画像が異なることだけを、真偽を描き分ける根拠にしない。

死体は現行で共有している汎用の外見へ別名をまとめる。像は `generated` 由来の種別・性別ごとの表示外見を区別して扱い、死体の共通化と混同しない。像の全対象と、表示を許す区別の全集合はR3で照合する。

同じ元タイルへ複数のglyphが対応している場合は、入力側で区別していない外見を勝手に別画像へ分けない。汎用の死体画像などを種別・実体の情報から描き分ける拡張は、本仕様で自動的に許可しない。必要な表示差はR3でコアが許可する情報と照合し、外見対応表と検査を追加してから採用する。

アイテムとキャラクターが同じ数値の表示入力を使う場面は、表示先と表示分類も照合する。職業・種族選択などのキャラクター用キーはR3で定義し、アイテム用の表へ無理に押し込めない。品物のコア変換が幻覚中の像をキャラクター分類として返す場合は、持ち物・装備欄・メニューでもその分類を許可し、R3のキャラクター表へ振り分ける。アイテム表にないからといって診断エラーや実物の像へ戻してはいけない。

### 3.2 制作担当へ渡す情報

Antigravityへの制作依頼は、外見グループのキー、表示できる外見名、形・色などの説明、必要な向き・コマ、R1の納品条件を使う。同じ外見を持つ本物と偽物、効果の違う品物には別の依頼を作らない。

元の `objects.txt` の注記には、外見と真の名前が併記されている。注記をそのまま制作依頼へ渡さず、隠された真偽・効果名を除いた外見情報を作る。真の種類との対応は内部の全件照合・試験用データに分け、制作台帳の公開する外見定義、画像名、通常の監査出力へ流さない。外見記述がない場合に登録する、コアが最初から表示する名前もこの条件で審査する。

### 3.3 実行時の変換

```text
コアが表示用に選んだglyphとtileidx・表示フラグ
  → 表示分類を判別（実体の種類へ戻らない）
  → 版付きの静的対応表を、受け取ったtileidxで参照
  → 許可された表示分類と別名を照合
  → 同じ外見のグループ共通のキーを得る
  → R1の共通画像解決・監査へ渡す
```

- `glyph - GLYPH_OBJ_OFF` などで真の種類を計算し、その種類名でPNGを引く処理は禁止する。
- `objects[otyp].oc_descr_idx` を描画時に直接調べ直す方法も採用しない。コアの汎用表示・幻覚・記憶表示を迂回するためである。
- 台帳の版が違う、タイル番号が見つからない、表示分類が一致しない場合はR1の診断エラーとする。近い番号や真の種類から推測して画像を補わない。
- 鑑定状態、呪い、祝福、未確認の材質・中身・充填数・アーティファクトなどで原画像を変えない。既存の名前・枠・表示記号は、コアがすでに表示を許した結果だけを重ねる。
- 途中の確認版で旧画像を許可しているグループも、元のタイル番号の違いをそのまま描き分けない。同じ外見グループに登録した代表タイルへ正規化し、同じ旧外見を使う。代表は静的表で固定して記録する。

## 4. 表示用スナップショットと更新

通常マップはコアから受けた表示情報を保存する。持ち物・装備欄など実体への参照を持つ画面では、既存のコアの表示変換を行う接続部分で表示情報を一度作り、描画側へ渡す。PNGを読む処理からコアの品物へ再度問い合わせない。

表示用スナップショットには、外見の `tileidx`、表示分類、許可された表示フラグ、版、更新世代を持たせる。物体IDは内部の対応付けに使えても、画像キーや外部の監査記録に使わない。真の `otyp`・効果名・未表示の実体情報を画像キャッシュや監査の識別子に混ぜない。

シャッフルされない品物では、生の `tileidx` 自体が真偽などの違いを含むため、通常の監査記録・確認用表示・画像キャッシュの識別子には外見グループのキーを使う。生のタイル番号、元の素材内番号、タイル内の座標、真の種類に結び付くglyph番号を、品物ごとの出力に残さない。入力の内部参照と、版付きの静的対応表の索引にだけ使用する。分類できない場合の診断も、匿名の事象番号と理由を示し、元の識別番号を公開しない。元の識別子が必要な再現試験の正解データは、通常の監査とは分けて管理する。

| 場面 | 扱い |
|---|---|
| 外見未確認の品物 | コアの汎用glyphと対応タイルをそのまま新しい汎用画像へ解決する |
| 外見を確認したが効果は未鑑定 | シャッフル後の外見タイルで画像を選ぶ |
| 鑑定した品物 | 外見は維持し、コアが表示する名前・既存の識別情報を更新する |
| 通常と積み重なり先頭 | 同じ外見タイルなら同じ原画像を使用。先頭の印は表示フラグに従い、下に隠れた品物の実体を見ない |
| 死体・像 | コアの表示glyph・タイルと静的表の対応を使用する。`corpsenm` や性別などを実体から追加取得しない |
| 幻覚 | コアが選んだ表示分類を使う。像がキャラクターに見える場合は品物の表示先からもR3のキャラクター表へ解決し、実物の像へ引き戻したり診断エラーにしたりしない |
| 視界外・記憶・検知 | 受け取った表示または記憶のスナップショットだけを使い、現在の実体から更新しない |
| 非公開の容器の中身 | コアが中身を表示する操作を許可するまで、画像を取得・表示しない |

幻覚などの表示を、`paintEvent`・ドラッグ画像・キャッシュ照合で新しく抽選しない。同じ表示更新の描画は同じスナップショットを再利用し、コアが次の表示更新を出したときに更新する。画面間で表示更新の時点が違う場合は、異なる表示結果になることを許容する。乱数の消費箇所とゲーム状態の不変検証はR6でも確認する。

品物の観察・識別、コアによる表示更新、幻覚の開始・終了、セーブ復元、ゲーム開始、素材対応表の版変更で表示キャッシュを更新する。実体IDだけで別のゲームや古い外見を再利用しない。静的な外見キーからPNGへのキャッシュと、物体から現在の外見への対応は別に管理する。

## 5. 保存・言語・ビルドへの対応

- 外見シャッフルはコアだけが行う。画像制作・変換ツールやQtが新しい乱数で外見を並べ替えない。
- 保存・復元はコアの既存の `objects[]` と `restnames` に従う。復元後にコアが再構成した対応から表示スナップショットを作り直す。新画像のためにセーブ形式を変更しない。
- R1の標準タイル変換では、実行時にシャッフルされた品物ではなく、静的対応表の各外見グループに属する**すべての外見タイル番号**へ、同じ新しいサムネイルを配置する。コアの `shuffle_tiles` がその対応を選べる状態を維持する。
- 英語・日本語でキーやファイル名を翻訳しない。対応表が一致するビルドは同じPNGを使う。一致しなければ片方の番号表を流用せず、差を検査して停止する。
- ソースやタイル構成が変わったときは、対応表と配置検査を再生成する。既存セーブの互換性の判定はR5で扱い、対応表のキャッシュが古い状態を互換性と混同しない。

## 6. 漏えいを防ぐ検査

同一画像の比較は、48×48の原画像か、寸法を揃えた画像部分で行う。呪いなどが既知の場合の枠・文字、画面ごとの拡縮、積み重なりの印と、原画像の違いを混同しない。実体の正解を扱う検査用データは、通常の監査出力や利用者向けの表示と分離する。

| ID | 検査 | 合格条件 |
|---|---|---|
| I-01 | 同じ外見に異なる真の種類を割り当てたゲームを比較 | 乱数シード・効果・元のタイル番号が違っても、同じ外見グループのキー・原画像・ハッシュになる |
| I-02 | 同じ真の種類に異なる外見を割り当てる | 効果名や `otyp` ではなく、コアが選んだそれぞれの外見画像になる |
| I-03 | 同じ外見のまま鑑定前後を比較 | 原画像は変わらず、許可された名前・既存の識別表示だけが変わる |
| I-04 | 外見未確認・遠方・盲目と、観察後を比較 | コアが汎用表示を選んでいる間は色・形を補わない。コアの観察後だけ具体的な外見へ更新する |
| I-05 | 迷宮・持ち物・装備欄・メニュー・ドラッグの対応 | 同じ表示入力は同じ原画像へ解決され、直接 `otyp` へ戻る経路がない |
| I-06 | 積み重なり、汎用品物、死体、像、幻覚 | 別の表示分類を正しく解決し、実体の種類・中身・下の品物を画像から補わない |
| I-07 | 同じ表示更新を繰り返し再描画する | 同じスナップショット・画像になり、描画を理由に再抽選や観察・識別を行わない |
| I-08 | 保存・終了・再開 | コアの外見対応が復元され、再抽選や以前のゲームのキャッシュ混入がない |
| I-09 | 英語・日本語の同じ対応表 | 外見キーと原画像は一致し、言語だけで画像を変えない |
| I-10 | 名前、ファイル名、キャッシュキー、監査記録 | 未鑑定品の真の種類、効果名、生のglyph・tileidx・素材番号・画像内座標からの識別が混入しない |
| I-11 | 対応表・版・分類の不整合と欠損 | R1の診断へ進み、真の種類や古い画像で補わない |
| I-12 | 未公開の状態だけを変える対照検査 | 未知の祝福・呪い・中身・効果・材質等を変えても、許可された表示入力が同じなら画像も同じになる |
| I-13 | シャッフルされない同じ外見の全対象を比較 | 本物・偽物の魔除け、灰色の石、袋、ランプ、角笛、同じ色の宝石などについて、同じ外見グループに属する全タイルの原画像・ハッシュ・サムネイルが一致する。途中版の代表旧画像と通常の監査識別子もグループで一致する |

I-01・I-02は「シードが違う」という条件だけでは不足する。試験用のコア状態を検査し、本当に同じ外見／異なる真の種類、または同じ真の種類／異なる外見になったケースを採用する。再現する方法とセーブはR5で用意する。検査対象がなければ未検証とし、成功を推定しない。

I-13は元のタイル番号が異なるケースを必ず含める。個々の素材が新規作成でも、同じ外見の本物・偽物に別の画像を割り当てていれば不合格にする。幻覚中の像については、持ち物・装備欄・メニューからキャラクター表へ進み、新素材で描けることをI-05・I-06で確認する。

フェーズ2は代表アイテムで、フェーズ5は制作台帳の全対象で該当項目を検証する。各確認版の手動確認に加え、各フェーズの区切りでClaude Codeレビューを行う。

## 7. 変更対象と今回の確認範囲

実装時の主な変更対象は `src/qt_darkdungeon.cpp`、`src/qt_inventory.cpp`、Qt装備欄・メニューへの接続を生成する `scripts/prepare-source.ps1`、素材台帳の生成・受入検査、R1の標準タイル変換。原画制作はAntigravityへ依頼する。
