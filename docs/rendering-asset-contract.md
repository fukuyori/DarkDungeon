# R1: 画像形式・配置・旧画像への切替に関する実装仕様

作成日: 2026-10-27

状態: R1の仕様確定済み。2026-10-27の[Claude Code最終再レビュー](../artifacts/claude-r1-asset-contract-final-review-20261027.txt)で、R1の完了を妨げる矛盾・未決定はないと判定された。ゲームの実装・動作検証の完了を意味しない。

この文書は [表示品質仕様](rendering-parity-spec.md) のR1対応を定義する。ここで定めるローダー、台帳、検査、配置処理はフェーズ2以降に実装するもので、現時点で動作する機能の説明ではない。R1の完了は、この仕様の整合性を確認することを指す。

## 1. 決定事項と担当

| 項目 | 決定事項 |
|---|---|
| 画像の制作 | Antigravityへ依頼する。主人公、敵・仲間・NPC、全アイテムを作り直す。ロク（本作業を担当するCodex）は依頼仕様の整理、受入検査、組み込み、動作確認を担当する |
| 原画 | 1コマ48×48画素、各色8bit RGBA（PNG color type 6）。アルファは0または255に限る。不透明画素に予約背景色RGB(71,108,108)を使わず、黒い輪郭を背景色として消さない |
| キャラクターのシート | 上・右・下・左の4行。列数は素材ごとに台帳で宣言する。幅は48×列数、高さは192。基準は4列＝192×192で、6列なら288×192として扱う |
| アイテム・静止した記号 | 48×48のPNG。アイテムの外見キーとコアのシャッフルへの接続は [R2の外見仕様](item-appearance-contract.md) に従う |
| 描画寸法 | 原画から独立させる。地形48×48、キャラクターの描画枠72×72は比較開始値であり、72×72の原画を要求するものではない |
| Rogueレベル | レモンの指定により、ほかの階と同じ新素材で画像表示する。階に入ったことを理由に文字表示へ自動切替しない。階固有のゲームルールは維持する |
| 配置 | プロジェクト内と各言語のアプリ内で同じ `sprites/` 以下の構成を使う。台帳は `sprites/manifest.json` とする |
| 旧画像の暫定表示 | フェーズ2〜5の途中の確認版で、台帳に明示した未置換対象だけ許可する。新素材の読込失敗を旧画像で自動的に隠さない |
| 完成時 | 旧画像の使用指定・描画・配布残存と、予期しない代替表示が0件。全対象の照合と通常画面での確認を合わせて判定する |

R3で追加した起動・セーブ選択用イラストはglyph用シートとは別で、196×111の単画像とする。RGBA8 PNG、0/255アルファ、予約色禁止、制作元記録は共通条件とし、文字は埋め込まずQt側の翻訳可能な表示で扱う。Qt内蔵の仲間印・縮小仲間印・積み重なり印も新素材へ接続し、48×48の原画と表示寸法（8×7、5×5、5×5）の検査を分ける。

列数だけから動作を決めず、台帳に各動作のコマ番号を宣言する。基準の4列は待機兼歩行A、歩行B、攻撃準備、攻撃実行。追加コマも同じ48画素の格子に置く。必要な動作、コマ順、再生時間、種類ごとの例外はR4とフェーズ3・4で確定する。ローダーは宣言した寸法とコマ範囲を検査し、現行の192×192固定による拒否を置き換える。

この版ではキャラクターシートの行数は4固定とし、台帳の行数宣言も4以外を拒否する。同時に合成する主人公の部位は、列数・動作のコマ宣言・接地点を一致させ、不一致を検査エラーとする。方向のない種類の動作の選び方はR4で定義し、4行の格子内に同じ姿を配置することは許可する。48画素の原画と4方向は今回の形式の前提であり、大型敵の描画倍率や将来の8方向化を決めるものではない。異なる原画形式が必要になった場合は、台帳の形式バージョンを変更して再レビューする。

描画とサムネイル生成の拡縮は最近傍補間を使い、平滑化・アンチエイリアスによる境界色を追加しない。48から72への非整数倍では、原画1画素が画面上で1または2画素になる不均一さは許容する。整数倍率の完全な画素幅統一とは説明せず、実際の見やすさと倍率の採用はフェーズ2の新作をG48で撮影したネイティブ表示で確認する。

[R7](rendering-comparison-contract.md)のG36は旧比率/構図の診断条件であり、48→54の1.125倍、地形48→36の0.75倍を伴うため新原画の画素品質の合格に使わない。G48でも実DPRを含めた非整数倍率を記録し、原画1:1の検査とネイティブ表示の判読を分ける。原画48・4方向等の形式を変更するものではない。

Antigravityからは、透過PNG、コマと接地点の説明、制作元データまたは再編集可能な成果物、納品一覧を受け取る。既存画像の拡大・色替え・名前変更だけでは新規制作と認めない。制作依頼を実際に送った日時・依頼内容・納品内容を記録し、未送信を依頼済みとしない。接続方法が未確認でも、R1の形式定義と受入条件の整理は進められる。

このPCの `agy` CLIから納品条件の確認依頼を送信できることは確認した。経路と回答は[Antigravityへの依頼手順](antigravity-image-workflow.md)に記録する。画像生成と品質検査は制作フェーズで行う。

## 2. 現行ソースとの対応

| 確認した現状 | 実装で変更すること |
|---|---|
| `src/qt_darkdungeon.cpp` の `spriteSheet` は192×192以外を空画像として返す | 台帳で宣言した48画素格子・行数・列数・透過形式を検査する。寸法不正を診断へ渡す |
| `heroSheet` は合成画像を192×192固定で作る | 部位に共通する台帳の列数と4行から合成寸法を作り、不一致を拒否する |
| 動作の列番号・静止プレビュー・実行時検査に固定値がある | `animationColumn`、`darkdungeon_hero_image`、透過検査・素材読込検査も同じ台帳のコマ定義へ接続する |
| `drawActorSprite` が失敗すると、マップ描画は標準タイルへ戻る | 「未置換として許可済み」と「新素材の異常」を分け、後者から旧タイルを引かない |
| マップと `src/qt_inventory.cpp` のアイテム画像は標準タイルを使う | 表示可能な外見に対する共通の画像解決処理を経由させる。外見キーと真のアイテム種別を混同しない |
| 上部装備欄の `win/Qt/qt_inv.cpp` は `drawBorderedCell` を使う | 独立した持ち物ウィンドウだけでなく、この装備欄も新素材へ接続する。生成元は `prepare-source.ps1` で管理する |
| Windows・Unixのビルドは `hero`、`monster` のPNGをコピーする | 以下の台帳と全グループを、英語・日本語の両方へ検査付きで配置する |

ソースの確認は仕様作成の根拠であり、新しい処理を実行した検証結果ではない。

### 2.1 描画経路の照合表

フェーズ2で次の各呼び出しを照合し、画像解決処理を迂回する経路を残さない。低レベル関数の入口でも表示先を記録し、未分類の呼び出しは監査の不合格とする。

| 表示先・呼び出し | 採用する経路 |
|---|---|
| 通常マップの `darkdungeon_draw_map_cell` と `drawActorSprite` | 新素材の共通解決。キャラクター・アイテムを標準タイルへ流さない |
| `win/Qt/qt_map.cpp` のタイル描画分岐の `drawCell` | 同じ共通解決へ接続する。生成後の実際の分岐を照合する |
| `src/qt_inventory.cpp` の `itemImage`、`darkdungeon_hero_image` | 新素材の共通解決。静止プレビューも台帳のコマを使う |
| `win/Qt/qt_inv.cpp` の `drawBorderedCell` | 新素材の共通解決。枠・反転・呪い等の既存表示意味を維持する |
| `win/Qt/qt_menu.cpp` の `glyph`（品物選択等のアイコン） | 新素材の共通解決。表示先をメニューと記録する |
| `win/Qt/qt_plsel.cpp` の `drawGlyph` と職業・種族アイコンの `glyph` | 新素材の共通解決。表示先をキャラクター選択と記録する |
| `NetHackQtGlyphs` の `glyph`、`drawGlyph`、`drawCell`、`drawForegroundCell`、`drawBorderedCell`、反転画像・キャッシュ生成 | 呼出元の表示先・外見キー・解決結果を引き継ぐ。キャラクター・アイテムの未分類描画や無断のタイル経由は不合格 |
| 地形などキャラクター・アイテム以外の標準タイル描画 | R3の対象分類と対応付けて維持する。監査の対象外とする理由を記録する |
| `qt_map.cpp` の文字描画分岐（Rogue階層、`ascii_map`、タイル読込失敗による強制切替） | Rogue階という理由の自動文字化を除き、新素材の画像解決へ接続する。利用者が明示したASCII表示は既存機能として維持し、文字モード・選択理由を監査する。読込失敗による強制文字化は診断エラー |
| 旧画像との比較を目的とした検査専用の直接参照 | 通常描画から分離し、比較資料の読取と記録する。通常表示の旧画像0件の集計へ混ぜない |

現存する `build/` には古い生成ファイルが残ることがあるため、ファイルがあるだけで実行対象と断定しない。`src/` と `prepare-source.ps1` から英語・日本語を再生成したソースと実際のビルド対象を照合し、上表の関数の呼び出しを再検索する。Unixのパッチ適用後も同じ照合を行う。

画像表示の品質判定は、Rogueレベルを含めて画像モードで行う。利用者が明示的に選んだASCII表示は別の確認項目として記録し、旧画像0件の画像検証や新素材の動作確認の代わりにしない。文字表示から画像表示へ戻したときは、同じ新素材の解決・監査処理へ復帰する。画像欠損などによる意図しない文字表示を、利用者が選んだASCII表示と記録してはいけない。

### 2.2 意図した特殊状態の分岐

幻覚・飲み込まれ・変化・不可視の印・検知など、現在 `drawActorSprite` が描画を見送る分岐を「素材欠損」と一括扱いしない。コアの表示結果に対応する新素材で解決するか、台帳に登録した特殊状態へ分類する。分類の全集合はR3で確定する。主人公プレビューで画像がないときに輪郭だけを描く現在の経路は、正当な特殊状態として登録されている場合を除いて診断扱いにする。

## 3. 配置と台帳

```text
sprites/
  manifest.json
  hero/          主人公の新しい部位・動作シート
  monster/       敵・仲間・NPCの新しいシート
  item/          全アイテムの表示上の外見、死体・像
  fallback/      新しく作成した特殊状態・診断用の静止画像
  ui/            状態アイコン、仲間・積み重なりの印、起動・セーブ選択用画像
```

配置先は確認版を含め、各言語のゲーム本体と同じ階層にある `sprites/` とする。`ui/`も配置・ハッシュ・実際に読み込んだ画像の監査対象に含む。起動・セーブ選択の旧`nhsplash.xpm`は新しい共通画像への接続後に配布から除き、旧ファイルを代わりに読み込まない。プレビュー、依頼文、制作元データは実行時の画像としてコピーしない。制作元と納品記録は、配布するソースから由来をたどれる場所で管理する。

台帳の形式はバージョン1から始め、次の情報を持たせる。

- 素材のキー、種類、`sprites/` からの相対パス、SHA-256、制作元・納品記録への参照。
- コマの幅・高さ、行数・列数、各動作のコマ番号、接地点。
- 新素材の対応状況と、途中の確認版で旧画像を使う外見キーの許可一覧。
- 特殊状態のために意図して使う新しい共通画像のキー、適用条件、通常表示への復帰条件。

絶対パス、上位ディレクトリへの参照、キーの重複、同じキーの新素材と旧画像許可一覧への重複登録、宣言範囲外のコマ、ファイルとの寸法・ハッシュ不一致は検査失敗とする。ファイル名はASCIIで安定した名前とし、英語・日本語で画像を分けない。外見キーの全集合と対応漏れはR2・R3で定義した台帳と照合する。

段階的な確認版と完成版を、台帳に記録した検査モードで区別する。

| モード | 許可する状態 | 不合格となる状態 |
|---|---|---|
| `incremental` | 許可一覧に明示した対象のみ旧画像を使用。使用対象・残数を確認結果へ記載 | 一覧にない旧画像への切替、新素材の欠損、宣言不正、予期しない診断用代替 |
| `complete` | 全対象を新素材へ置換済み。特殊状態用の新しい共通画像は定義した条件で使用可 | 旧画像の許可一覧が残る、旧画像が描かれる、予期しない診断用代替、台帳や配置の不整合 |

フェーズ0・1の比較元は現行表示として記録し、旧画像0件の確認済みビルドとは呼ばない。新しい台帳と切替検出はフェーズ2で実装し、フェーズ5の完了判定とフェーズ6の確認版には `complete` を使う。

## 4. 画像解決と代替表示の規則

1. コアが表示を許した外見キーと表示先を受け取る。画像を選ぶために隠れた実体情報を追加取得しない。
2. 台帳に新素材がある場合は、その素材を解決する。読込・宣言が正常なら新素材を描く。
3. 未置換のキーが `incremental` の許可一覧にある場合に限り、コアから受け取ったタイルをR2の外見グループへ正規化し、そのグループに登録した代表旧タイルを使用する。同じ外見を元の種類で描き分けず、旧画像使用として記録する。
4. 新素材がない、壊れている、宣言が不正、許可一覧にもない場合は診断エラーにする。この経路から旧タイルを取得しない。
5. 実行中の異常で画面を更新する必要がある場合は、新しい診断用画像を描く。その画像も使えない場合は、画像ファイルに依存しない単純な診断図形を描く。どちらも検査上の不合格を隠さない。

診断用の代替と、不可視・検知・幻覚などを表す意図した新しい画像を区別する。正しく選択された特殊状態用画像は異常扱いにしない。診断図形は未制作画像の完成品として扱わない。全キャラクター・全アイテムの作り直しを、特殊状態や共通画像を理由に免除しない。

起動前に必要ファイルと台帳を検査し、異常があれば対象と理由を英語・日本語で示してゲーム開始を中止する。起動後に発生した異常は診断用表示と記録を残し、当該の確認を不合格にする。無言の終了、無言の旧画像への切替、空画像だけの表示は採用しない。

## 5. 旧画像使用の検出と0件の判定

検出は通常マップ、独立した持ち物ウィンドウ、上部の装備欄、主人公プレビューなど、キャラクター・アイテムを描く全経路で共通化する。描画先を増やしたときは台帳と監査対象も増やす。

確認版の監査記録には、次を保存する。

- ビルド識別子、台帳と実行ファイル・素材のハッシュ、言語、検査モード、検証場面。
- 表示先、R2で正規化した外見グループのキー、解決結果、新素材または代表旧画像の参照先、診断理由。通常の品物ごとの記録に生の `tileidx`・glyph番号・素材番号・タイル内座標を残さない。シャッフルされない品物ではそれら自体が正体を漏らし得るため、入力側の番号の差は通常の監査識別子にしない。
- 特殊状態用の画像を使った場合は、その素材キー、特殊状態の分類キー、適用条件の判定結果、復帰した事実。実体情報を追加取得せず、コアが表示へ渡した状態だけを記録する。
- 旧画像を許可する未置換キーの件数と、実際に旧画像を描いた対象の件数・描画回数。
- 想定外の診断用代替の対象と回数。重複行をまとめても、発生した事実と総数は失わない。

ゲーム画面には残件・旧画像使用・診断エラーの件数を確認用の情報として示し、詳細は確認版専用の記録へ出す。未鑑定品の真の種別や隠れた敵の実体情報を表示・記録しない。

条件を満たさない特殊状態用画像の使用は、許可された代替表示ではなく監査の不合格とする。`complete` ではキャラクター・アイテムを標準タイル経由で描いた時点で、タイルの中身が新しいサムネイルであっても経路違反とする。旧画像の検出と、低品質の迂回経路の検出を両方行う。

完成の0件判定は、次のすべてを満たすこととする。

1. R2・R3の外見・表示対象の全集合と照合し、新素材の対応漏れと旧画像の許可指定が0件。
2. 全表示経路の通常検証で旧画像使用と予期しない診断用代替が0件。
3. `sprites/` の配布内容が台帳の新素材と一致し、旧画像や未参照の古いファイルが残らない。
4. 標準の `nhtiles.bmp` 内のキャラクター・アイテム用タイル領域も、新素材から生成した静止サムネイルへ置換済み。これらは現行の選択画面等でも使われる領域であり、「未使用だから検査不要」としない。地形など別対象の領域とタイル対応番号は維持する。外見への対応はR2の定義に従う。
5. 未表示の対象を含む全件照合と、通常画面での表示確認を両方実施している。短時間のプレイで旧画像を見なかっただけでは0件の証明としない。

新規制作であることは、納品記録・制作元・比較画像と品質確認で確かめる。ハッシュが変わっただけで作り直しを証明できるとは扱わない。診断の故障注入検査は通常の0件検査とは別に記録する。

## 6. ビルドへの組み込み

- フェーズ2で `scripts/build-release.ps1` と `scripts/build-unix.sh` を変更し、台帳、`hero`、`monster`、`item`、`fallback`、`ui`を必要ファイルの一覧に従って配置する。
- 入力側の素材と配置後の素材の双方を検査する。宣言だけあってPNGがない、言語片方だけ欠ける、ハッシュが違うなどの場合はビルドを失敗とする。
- 確認版はビルド識別子ごとの新しいフォルダーへ作成する。通常配置を含むWindows・Unix両方の配置で、生成物の `sprites/` だけを作り直し、検査済み台帳の必要ファイルを置く。ゲームのセーブ・設定がある親フォルダーを消さず、配置後のファイル一覧が台帳と一致することを検査する。削除・再配置の対象はアプリ内の生成素材ディレクトリだと絶対パスで検査する。
- 主な実装対象に `src/qt_inventory.cpp`、Qt装備欄への接続を生成する `scripts/prepare-source.ps1`、Windows・Unixの素材配置スクリプトを含める。
- フェーズ5で標準タイル内の対象領域の新素材への置換まで完了し、フェーズ6で英語・日本語の配置内容と実際の表示を照合する。Unix用パッチと実行確認の範囲も別々に記録する。

起動画像の切替は、Qtの`qt_bind.cpp`・`qt_svsel.cpp`の読込だけでなく、`scripts/build-release.ps1`の旧画像コピー、`scripts/build-launcher.ps1`の必須ファイル一覧、Unixの`sys/unix/hints/linux.501`・`macOS.501`の`VARDATND0`を変更対象とする。生成元・Unixパッチも同時に更新し、フェーズ5-4で旧`nhsplash.xpm`への依存と配布残存をなくす。フェーズ2〜5の途中で旧起動画像を許す場合も、`ui.splash`を旧画像許可一覧に明記した確認版に限る。墓石`rip.xpm`はR3のUI背景として別扱いにし、起動画像とまとめて削除しない。

### 6.1 標準タイルの置換工程

現在のQtは1タイル16×16・1行40タイルを扱う（`win/Qt/qt_glyph.cpp`、`include/tile2x11.h`、`win/share/tile.h`）。Windowsは生成した `src/tiles.bmp` を `nhtiles.bmp` としてコピーし、Unixは `sys/unix/Makefile.dat` の `tile2bmp` で `dat/nhtiles.bmp` を生成する。これらの入力・タイル対応番号を壊さず、生成後に共通の変換工程を挟む。

- フェーズ2で共通のNode.js変換ツールを新規追加し、元のBMP、素材台帳、R2・R3で確定するタイル番号と新素材の対応表を入力にする。原本BMPは比較用に残し、別の出力BMPを生成する。
- 対応表は「単一素材キー」と「合成定義」のいずれかを参照する。合成定義は部位キー、向き別の合成順、着色条件、共通のコマと接地点を含む。主人公・職業アイコンは実行時と同じ部位合成規則から静止画像を作る。代表にする種族・性別・属性と外見の対応はR2・R3で定義し、変換ツール側で推測しない。
- 単一素材または合成済み画像から、台帳で宣言した静止コマ・向きを取り出し、最近傍で16×16へ縮小する。原画と合成結果のアルファは0/255に限定し、中間アルファを検出した場合は受入検査に失敗とする。不透明な画素が予約背景色と一致する場合も失敗とする。アルファ0の画素だけをRGB(71,108,108)に置き換え、アルファ255のRGBはそのまま使う。
- 出力はパレット制限で色を変えない非圧縮24bit BMPとし、元BMPと同じ幅・高さ・タイル順にする。元のBMPとPNG・合成結果それぞれの検査を行い、変換ツール自身の出力を比較しただけで透過や輪郭が正しいと判定しない。
- BMP変換の対象領域はR3台帳の`replace-with-new-asset`と`clear-reserved-slot`に限定する。前者は宣言した新サムネイルへ置換し、後者は旧キャラクター・品物が残らないよう全画素を予約色RGB(71,108,108)へ消去する。地形の`environment-style-audit`と空領域の`preserve-empty-sentinel`は元のRGB画素をそのままコピーする。未探索・何もない・区切りの3枠に新たな予約色を注入しない。寸法や1行のタイル数が違う場合は推測で処理せず失敗とし、未分類があれば完成判定へ進まない。
- Windowsは `src/tiles.bmp` 生成後、アプリへ配置する前に変換する。Unixは `dat/nhtiles.bmp` の生成後に同じツールで変換し、`make install` 後の各言語アプリに検査済みBMPを配置する。未変換BMPが最終成果物を上書きしない順序にする。
- 検査は画像をRGB画素へ復号し、置換領域が宣言した新サムネイルと完全一致すること、元の対象画像がそのまま残っていないこと、47予約枠がすべて予約色であること、地形122枠と空領域3枠が元と完全一致することを別々に確認する。予約枠は通常描画で参照されないことも検査し、参照されたら診断にする。元から予約色だけの枠は画素差ではなく消去後の値で合格を判定する。BMP全体のハッシュ変更だけで置換を証明しない。
- 共通解決処理が使う新素材の検査は、この16×16サムネイルの検査とは別に行う。サムネイルで通常マップ・持ち物・装備欄・メニュー・選択画面の新素材経路を代用しない。
- `complete` の検証では、未変換の `x11tiles` や未検査のタイルファイルへ暗黙に切り替わった場合も不合格とする。Qtが実際に読んだファイルとハッシュを記録する。

共通変換ツールはNode.js 22以上を実装時の前提とし、Windows・Unix両方のビルド開始時にバージョンを確認する。見つからない・対応外の場合は処理を中止し、未変換の素材を代わりに配布しない。導入手順と前提条件の説明も、フェーズ2で両言語のREADMEへ反映する。

現在のスクリプトに新しいグループの配置機能がすでにあるとは説明しない。元のNetHack入力リポジトリや、通常のセーブ・設定を素材作成の出力先にしない。

## 7. R1に対応する実装時の検査

| 検査 | 期待する結果 |
|---|---|
| 48画素の4列シートと6列シート | それぞれ192×192、288×192として読込成功。台帳の各コマを参照できる |
| 部位シートの列数・接地点の不一致 | 合成前検査で失敗する。プレビュー・動作・実行時検査も台帳の同じコマを参照する |
| 主人公・職業アイコンの合成サムネイル | 向き別の順序・着色・コマを含む同じ合成定義から作り、実行時の合成結果を縮小した期待値と一致する |
| 原画48、描画枠72 | 原画を変更せず72の枠へ描画でき、接地点と透過が維持される |
| 48×48のアイテム | 迷宮・持ち物・上部装備欄で同じ外見キーから新素材を選ぶ |
| 台帳と寸法・ハッシュが不一致 | ビルドまたは起動前検査が失敗し、対象と理由が分かる |
| 画像欠損・破損、台帳キー欠落 | 起動前検査で失敗。起動後の故障注入では診断用表示を出し、旧画像使用で隠さない |
| 許可済み未置換キー | `incremental` だけで旧画像を表示し、全表示先で使用を記録する |
| 新素材の読込失敗 | 許可一覧を理由に旧画像へ戻らず、診断エラーとする |
| 許可一覧または旧画像使用が残る完成版 | `complete` の判定に失敗する |
| 正しい特殊状態用の新画像 | 診断用代替と区別され、隠れた情報を増やさない |
| 中間アルファまたは不透明な予約背景色を持つ原画 | 変換前に検査失敗とし、青緑の縁や輪郭の穴を含む画像を通さない |
| 適用条件外の特殊状態用画像 | 状態キーと条件判定を監査で検出し、不合格にする |
| 英語・日本語、Windows・Unixの配置 | 同じ台帳と必要素材が揃う。未実行OSは未検証と記録する |
| 古い素材・標準タイル領域の置換漏れ | 配置と全件・領域画素照合で検出し、完成版の判定に失敗する |
| メニュー・キャラクター選択・低レベル呼出しの迂回 | 呼出箇所の全件照合と実行時監査で検出する。新サムネイルが描けても経路違反は不合格 |
| Rogueレベルへ移動して保存・再開 | 明示的なASCII指定がなければ、新素材の画像表示を維持する。階を理由に文字表示へ切り替わらない |
| 利用者がASCII表示を選択してから画像表示へ戻す | 明示的な文字モードとして記録し、画像へ戻したら新素材と監査へ復帰する。画像欠損による切替は別の診断エラーとして検出する |
| Unixの通常配置に古い素材がある | `sprites/` の再配置とファイル一覧照合で解消し、セーブ・設定を維持する |

これらはフェーズ2以降に実装する検査であり、今回通過したテストの一覧ではない。R1の再レビューでは、形式・表示寸法・配置・切替規則・0件判定の矛盾がないかを確認する。R2〜R7の未解決事項まで完了したとは扱わない。
