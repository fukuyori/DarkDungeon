# 通常ゲームの表示を旧ドルアーガモードと同等にするための仕様

作成日: 2026-10-27  
状態: R1〜R7の仕様整理完了（2026-10-28）。現在のソースと保存済み画像を調査し、Claude Codeのレビューを経て整理した。フェーズ0以降の実装完了や動作品質の合格を示す文書ではない。

## 1. 目的と適用範囲

通常ゲームを遊ぶ画面で、削除前のドルアーガモードと同等の、キャラクターが大きく見分けやすく、移動・攻撃・画面追従が一続きに見える表示を実現する。「スプライトを追加した」「アニメーションが再生された」だけでは、同等になったとは判定しない。

本書でいう「旧モード」は、削除前の `RealtimeArena`（リアルタイム練習画面）を指す。既存の設計メモには、2026-10-10に削除したと記録されている。別画面として復活させず、その表示上の利点を通常ゲームへ取り込む。

対象は迷宮、主人公、敵、品物、地形、視覚効果、カメラ、およびそれらを囲む画面配置。ゲーム全体の英語・日本語対応を維持する。ゲームの進行、移動の成否、敵の判断、攻撃の命中、当たり判定、Spaceの意味などは既存コアの結果に従う。表示品質の移植とリアルタイムのゲームルールへの変更は別の作業として扱う。

原作のキャラクター・名称・外部画像の再導入は行わない。旧モードは表示の比較資料とし、実装には再利用条件を確認できる現行素材・独自素材を使う。素材の取り扱いは [設計メモ](design.md) と [第三者ソフトウェアの表示](../THIRD-PARTY-NOTICES.md) に従う。

**追加の必須要件（レモンの指定）**: キャラクターと各アイテムの画像はすべて作成し直す。主人公の選択可能な組み合わせ、敵・仲間・NPC、全アイテムの表示対象を網羅し、既存の画像をそのまま最終版へ残さない。現在の独自スプライトも作り直しの対象とする。描画・合成・生成ツールの共通処理を活用することと、既存の絵を残すことは区別する。

画像制作はAntigravityへ依頼する。ロクは依頼仕様の整理、受入検査、ゲームへの組み込みと動作確認を担当する。原画の形式、配置、旧画像への切替規則は [R1の画像実装仕様](rendering-asset-contract.md) に従う。[依頼経路と送信実績](antigravity-image-workflow.md)は仕様の決定と分けて記録し、条件確認だけを画像制作完了としない。

未鑑定品・未観察品の外見と新画像の対応、コアの外見シャッフルへの接続、情報漏えいの検査は [R2のアイテム外見仕様](item-appearance-contract.md) で定める。

## 2. 調査で確認した基準と現状

調査対象のGit HEADは `cee98f5`。開始時点で `src/qt_darkdungeon.cpp`、同ヘッダー、`scripts/prepare-source.ps1`、Unix用パッチ2本に未コミットの変更があった。以下の「現行ソース」は、その変更を含む作業ツリーを指す。`dist` の実行ファイルへの反映状況は今回検証していない。

| 比較項目 | 旧モードの保存ソースで確認した定義 | 現行ソースで確認した内容 | 本仕様で埋める差 |
|---|---|---|---|
| キャラクターの大きさ | 地形36×36に対し、主人公・敵を54×54の枠で描画。枠の比率は1.5倍 | 原画48×48の1コマを、基本的に1マスの矩形に描画 | マス寸法とキャラクターの見かけの大きさを分離する |
| カメラ | 主人公の連続座標を表示領域の中心へ置く | Qtマップのスクロール領域を利用。ズーム・リサイズ時のカーソル中心化がある | 表示座標と同じ時刻で追従させ、移動の途中で画面だけ先行させない |
| 更新 | 16ms周期のタイマー、実測経過時間、1/60秒刻みのモデル更新 | アニメーション更新タイマーは30ms周期 | ゲーム進行と描画更新を分離し、表示の連続性を揃える |
| 主人公の動作 | 4方向×6コマの合成画像。歩き2コマと剣の状態に対応したコマ | 4方向×4コマ。歩き2コマ、振りかぶり、打撃 | コマ数ではなく姿勢・位置・向きの変化が読める動作を完成条件とする |
| 部位の重なり | 向きによって身体・装備の合成順を変更 | 身体→髪→服→マント→武器→盾という共通の順 | 向きごとに前後関係を定義する |
| 敵 | スライム・騎士・魔法使い・竜の種類別画像と動作 | 犬などの専用画像と、怪物クラス別画像の種別色への着色 | 色の違いだけに依存せず、輪郭・動作を読み分けられるようにする |
| 待機中の動き | 敵のコマをモデルの経過時間から選択 | 歩行・攻撃が終わると静止コマへ戻る | スライムなどの動き続ける姿も表示だけで表現する |
| マス間移動 | 連続座標で描画 | 作業ツリーには移動補間とマップ全体への後描き処理がある | 補間、描画順、カメラ、連続入力を一体で検証する |
| 地形・重ね描き | 地形を先に、敵・弾・主人公を後に描画 | 独自の石積み・石畳、透過した前景、記憶地形の合成がある | 既存の視界制約を保ち、拡大したキャラクターも欠けずに重ねる |

仕様策定時の旧実装では歩行120ms×4段階＝480ms、攻撃140＋180＋60ms＝380msと定義されていた。目標値として承認されたものではない。2026-10-28にR6の#128で旧通知/位置推測を撤去し、新通知の接続までは静止表示とした（[結果](phase0-legacy-retirement.md)）。旧モードの16msはタイマー設定であり、実際に毎秒60フレーム描けていたという測定結果ではない。

現行ソースの `darkdungeon_view_defaults` では旧16×16設定を48×48へ移行する。24ピクセルのアイコンと下側の文字は `darkdungeon_start_hooks` など、メッセージ3行分と下部配置は `prepare-source.ps1` のQtレイアウト変換に定義されている。これは現状の実装の説明であり、画面配置が完成しているという判定ではない。欄の大きさ・余白・迷宮との配分はフェーズ1で改善する。現在の実行ファイルでの動作確認とも区別する。

旧画面と通常画面の保存画像も確認した。ただし、場面・表示範囲・ゲーム状態が異なるため、厳密な同条件比較ではない。静止画から入力遅延、動きの滑らかさ、性能の優劣を確定しない。利用者からの「旧モードに及ばない」という評価を、本書の改善要求の出発点とする。

## 3. 「同等」の判定

次のすべてを満たすことを完成条件とする。

1. 主人公と主要な敵が旧画面と同程度の存在感を持ち、向き・姿勢・行動が読み取れる。
2. 移動するキャラクター、歩行のコマ、カメラが同じ時間軸で動き、飛び・欠け・残像がない。
3. 攻撃の準備、実行、静止への復帰が見える。表示が命中や移動の結果を勝手に変えない。
4. キャラクターと全アイテムの画像が新しく作成・組み込み・動作確認され、地形を含めた画風と縮尺が揃っている。キャラクター・アイテムの旧画像残存と未対応が0件で、特殊状態用の新しい代替表示は理由と対象が明示されている。
5. 英語・日本語、通常サイズ・狭いウィンドウ・最大化のいずれでも、迷宮を中心に遊べる。
6. 第8節の検証と比較資料によるレモンの目視確認を通過する。旧動画がない動作の品質は、V-04・V-05の要件と新しい比較用動画を基準に判定する。

本書の「旧モードの値」は保存ソース上で確認した定義であり、保存画像を生成した実行ファイルとの一致や実測値を保証しない。「初期案」「目標」と記したものは実装・比較のための提案値であり、採用済みの仕様や達成済みの性能と混同しない。

## 4. 表示要件

### V-01 キャラクターの縮尺と接地

- 地形1マスの寸法と、キャラクターの描画枠の寸法を別々に管理する。初期案は旧モードと同じ1.5倍。地形48×48なら描画枠72×72とする。
- 描画枠を広げるだけでなく、透明部分を除いた身体・頭・武器の大きさを比較する。輪郭が細いまま余白だけ増えたものを合格としない。
- 主人公と人型の敵は共通の接地点を持つ。スライム、四足、飛行、大型の敵は種類別に接地点・高さを定義し、大きさを一律に揃えない。
- 向きやコマを切り替えても、足元が不自然に上下左右へずれない。身体の上下動を演出する場合も、接地点との関係を維持する。
- 武器・盾・頭がマス境界を越えても、隣のマスの再描画で消えない。旧位置と新位置を含む描画領域を更新する。
- 拡大に伴い隣のマスに重なる絵と、実際の占有マス・当たり判定を区別する。表示だけを理由に占有範囲を変えない。

### V-02 画風、輪郭、素材の網羅

- 主人公・敵は共通の見下ろし角度、光の方向、輪郭の太さ、影の濃さで描く。灰色の床でも身体と武器が埋もれない配色にする。
- ピクセルアートは原画の境界を保って拡縮し、ぼかしや透明画素の縁に色のにじみを生じさせない。高DPI環境でも論理寸法と画素寸法を混同しない。
- キャラクターと全アイテムを新たに描き起こす。既存画像の単純な拡大・色替え・名前変更だけで、作り直しが完了したと判定しない。新規素材の共通部位を組み合わせる場合も、対象ごとの完成した外見を検証する。
- 色だけでなく輪郭・大きさ・特徴的な部位で敵の系統を識別できること。既存のクラス共通画像を着色して残す方式は、最終版の要件を満たさない。
- 主人公は現行で選択可能な職業・種族・性別・属性の組み合わせを欠落なく扱う。変化中の姿は通常時の主人公画像で上書きしない。
- 主人公、敵・仲間・NPC、品物、死体・像の全対象をソースの定義と照合して一覧化する。制作前／制作中／作成済み／組込済み／動作確認済みを管理し、新素材のファイル・生成元・ゲーム内の表示先を対応付ける。地形とビーム・爆発も別枠で対応状況を記録する。
- アイテムは実際に表示する外見をすべて新規作成し、迷宮内、持ち物、装備欄で同じ新素材を使う。未鑑定時の外見と鑑定後の対応を管理し、未鑑定品を真のアイテムIDに対応した絵で描いて正体を明かしてはいけない。
- 特殊状態で共通の代替画像が必要な場合も、新しく作成した画像を使い、理由・対象・復帰条件を対応表に記録する。新素材の欠損・破損を旧画像への切替で隠さない。
- 「未対応」は表示目標を満たしていない対象であり、残っている間は表示全体の同等化を完了としない。フェーズ2〜5の途中の確認版では、R1で定める許可一覧の未置換対象だけ旧画像を暫定表示し、その対象と残数を示す。フェーズ5の完了時とフェーズ6は旧画像使用0件を必須とする。キャラクター・アイテムを「意図した既存表示」として作り直し対象から除外してはいけない。

### V-03 向きと部位の合成

- 上・右・下・左の各向きについて、身体、髪、服、マント、武器、盾の前後関係を定義する。正面の武器や背面のマントが逆に重ならないこと。
- 初期案は現行の4方向を維持する。斜め移動時の向きの選択を統一し、主人公と敵で判断を揃える。8方向画像の追加は別途判断する。
- 主人公だけでなく、方向を持つ敵にも4方向の静止・歩行・攻撃を用意する。スライムなど方向を区別しない種類は対応表で明示し、方向のない動作を定義する。
- 表示する装備は、ゲーム状態と矛盾しないこと。現行の職業固定の武器・盾を、実際の装備の表示と説明しない。
- 装備変更を外見へ反映する範囲は未決事項とする。採用する場合は実装対象を対応表へ追加し、未対応装備の共通表示も定義する。

### V-04 歩行とカメラ

- 移動が成立したイベントを受け、旧マスから新マスまで表示位置を補間する。描画のために移動コマンドを再発行したり、ゲーム内の位置を途中座標に書き換えたりしない。
- 移動の開始から終了までに、足の運びと身体の変化が見えること。画像の数や変更画素数だけで判定しない。停止時には足元が新しいマスに一致する。
- スライムの伸縮や飛行の羽ばたきなど、待機中にも動く種類は、その場で短い動作を繰り返す。待機表示だけでターンを進めたり、実際の敵を移動させたりしない。種類ごとの静止・歩行・攻撃の使い分けを素材対応表へ記録する。
- 主人公、敵、カメラは同じ単調増加する描画時刻を使う。カメラは補間後の主人公位置を基準とし、キャラクターが移動先へ着く前に画面だけ移動先へ飛ばない。
- 通常は主人公を迷宮表示領域の中心付近に保つ。マップ端では未探索領域の情報を追加せず、必要な余白を許容する。手動スクロール後の追従復帰は明示した操作で行う。
- 連続入力、移動後すぐの攻撃、複数の敵の行動でも、表示待ちが積み重なりゲームの実位置から離れ続けない。古い演出を短縮・統合し、最終状態へ必ず追いつく。
- テレポート、階移動、復元、複数マスの不連続な位置変更は歩行補間しない。壁や未知の場所を横切る経路を捏造しない。
- 壁へ進んで移動が成立しなかったときは歩行を開始しない。モーダル画面・非アクティブ状態から戻ったときは、古い経過時間で動作が暴走しない。
- カーソル枠は移動中のキャラクターと離れた場所で点滅させない。初期案は現行の移動中非表示を維持し、終了時に正しいマスへ戻す。

### V-05 攻撃・被弾・飛び道具

- 攻撃は、方向のある準備→実行→静止の変化として見せる。剣を持たない姿や敵にも、攻撃方法に合う動きを使う。
- 実際に選ばれた攻撃の結果に対応させ、単なる方向キー入力から攻撃演出を作らない。命中・失敗の結果を表示側で抽選しない。
- 被弾、遠隔攻撃、魔法、ビーム、爆発はゲームから通知された表示可能な位置・方向・結果を使う。攻撃通知が足りない経路は一覧化し、補うまで確認済みとしない。
- エフェクトは主人公や敵の輪郭を長時間隠さず、終了時に必ず消える。相手が死亡・消失・視界外へ移ったときに、その場へ古い画像を残さない。
- 飛び道具は、コアが表示を許した通過位置の列を受け取り、その経路に沿って連続して見えるよう描く。終点しか通知されない経路は通知の不足として扱い、途中の経路や貫通を表示側で推測しない。ビーム・爆発は別の効果として描き分ける。
- 攻撃の表示時間を理由に、命中判定・敵の手番・Spaceの基本動作を変更しない。実時間での剣の構えや敵の自律移動は本仕様の対象外とする。

### V-06 地形と重なり

- 描画順は、表示を許された背景地形→階段・扉などの地形上の図柄→品物→キャラクター→攻撃などの視覚効果→カーソル・対象表示を基本とする。
- キャラクター同士は接地点のY座標を基準に前後を決め、同じ位置では安定した順序にする。必要な壁の前面などは別の遮蔽規則を定義し、画面走査の順序任せにしない。
- キャラクターと品物の透明部分から床・階段が見えること。黒い輪郭を背景色と一緒に消さない。描画枠全体の四角い背景を付けない。
- 同じマスの品物も表示する場合は、コアが表示を許した情報だけを取得する。現在の前景glyphだけでは取得できない情報を、隠れた品物の実体から補ってはいけない。
- 壁は濃い灰色の石積み、床はより明るい灰色の石畳を基本とし、部屋・暗い部屋・通路の明暗を保つ。既存の[黒線修正の記録](design.md)で解消した描画不具合は再発させない。
- 壁の直線・角・交差と `S_stone` が同じ画風で接続し、元の斑点模様や太い黒線が境界に残らない。実際の未探索 `GLYPH_UNEXPLORED` の黒は維持する。

### V-07 視界・特殊状態・復元

- コアが表示した地形と記憶地形を使用する。再描画時に、見えていない現在の地形・敵・品物を読み込まない。
- 視界から消えた敵を、移動補間や追従カメラのために描き続けない。検知だけで見えた敵の下に未知の床・罠などを追加しない。
- 盲目、不可視、幻覚、変化、飲み込まれた状態はコアの表示意味を優先する。実際の敵種別や主人公の通常姿が漏れない専用表示または明示した代替表示を使う。
- アニメーションは表示上の一時状態とする。保存・復元後に途中の歩行・攻撃を再開せず、復元された位置から静止して表示する。
- 階移動・マップ消去・ゲーム終了では、敵IDの対応、背景の記憶、部位合成、補間中の描画予約を適切に更新・破棄する。

### V-08 画面配置と言語

- 画面配置は改善対象とする。これまでの希望である、上部の装備・ステータス、中央の迷宮、下部の不透明なメッセージ欄、その下のツールバーという並びを基準とし、各欄の寸法・余白・占有率は現状の値で固定しない。
- メッセージ欄は横幅いっぱい、通常3行分を初期案とし、文字の読みやすさと迷宮の広さを実際の操作で調整する。
- ツールバーはアイコンの下に操作名を置き、横幅に応じて1段・2段を切り替える。アイコン24ピクセルは初期案として比較し、ボタン幅・高さ・間隔・段数の切替位置を改善する。最大化で無駄に大きくせず、狭い画面でも操作を欠落させない。
- 迷宮へ残りの領域を優先して割り当てる。上部だけが拡大したり、表示幅への縮小合わせでキャラクターが小さくなったりしない。
- 表示マス数は迷宮領域の寸法を地形寸法で割って管理する。比較用の初期案は迷宮領域864×432で、地形36なら24×12マス、標準48なら18×9マスとする。フェーズ0は現行画像の実寸を記録し、54/72の枠は目標値として別欄へ置く。地形36のG36は比率/構図の診断用で、フェーズ2の新原画の画素品質合格には使わない。原画の1:1検査とG48の実表示の判定は[R7](rendering-comparison-contract.md)に従う。
- ズーム時には地形とキャラクターの縮尺比を保ち、カメラの基準も同時に更新する。縦横寸法を別々に設定できる既存機能を維持する場合は、その組み合わせでも欠けを検査する。
- 英語と日本語で同じ描画処理と素材を使う。文章量の違いによって迷宮やツールバーが押し出されないようにする。
- Rogueレベルもほかの階と同じ新素材で画像表示し、階への移動で自動的に文字表示へ切り替えない。利用者が明示的に選ぶASCII表示は既存機能として維持する。画像欠損による強制的な文字表示は診断エラーとし、画像表示の検証を文字モードで代替しない。Rogueレベル固有のゲームルールは変更しない。

## 5. 実装の構成案

既存の `darkdungeon_draw_map_cell`、移動補間、透過処理を土台とする。別のゲーム画面や別のルールエンジンは追加しない。

```text
コアが確定した、表示可能なマップ更新と行動結果
  → 表示用スナップショット（地形・前景・識別子・可視性）
  → 歩行・攻撃の表示状態（旧位置／新位置／向き／開始時刻）
  → 同じ描画時刻で位置とカメラを算出
  → 背景・地形・品物を描画
  → マスを越えるキャラクターをまとめて描画
  → 効果・カーソルを描画
```

- 描画中にゲームルールを実行しない。表示用スナップショットには、非表示の実体情報を持ち込まない。
- 主人公・敵の識別子と階の世代を分け、別の敵や別の階へ古い動作を引き継がない。
- マスごとの描画と、マスを越える描画を分離する。部分再描画でも予約が前のフレームから残らず、必要な全領域を更新する。
- 画像の読込・着色・部位合成はキャッシュし、通常のフレーム描画で再生成しない。素材の欠損・破損はR1の診断エラーとし、新しい診断用画像または図形を使う。この表示を完成品や検査合格として扱わず、旧画像へ自動的に戻さない。
- Windowsの生成元は `src/` と `scripts/prepare-source.ps1`。`build/` だけを直接修正して完成としない。共通変更はUnix用パッチにも反映し、英語・日本語の生成結果を揃える。

## 6. 数値の初期案と決め方

| 項目 | 初期案・目標 | 決定・確認方法 |
|---|---|---|
| 地形の標準寸法 | 現行の48×48を維持 | 旧画面と同じ迷宮表示領域で比較する |
| 人型の描画枠 | 地形の1.5倍。標準時72×72 | 旧モードの比率を出発点とし、身体の実寸・接地・隣接時の視認性で調整する |
| 描画更新 | 約16ms間隔、60fpsを目標 | 同じ機材・同じ場面でフレーム間隔を記録する。達成値は実測後に記載する |
| 歩行・攻撃時間 | 現行480ms／380msを比較開始値にする | 単発と連続入力の動画で確認し、演出の読みやすさと操作の追従を両立する値へ調整する |
| 最初の表示変化 | コアの表示通知から50ms以内を95百分位の目標にする | 入力から通知までの時間も分けて記録し、描画の遅延とコアの処理時間を混同しない |
| 表示待ちの上限 | 各キャラクターの待ちを次の1動作までに制限。最後の通知から最長動作時間＋2描画周期以内に最終位置・姿勢へ到達 | 連続入力と敵が多い場面で計測する。初期値なら480＋約34＝約514ms。待機中の周期動作は継続してよい |
| ウィンドウ | 960×640、1395×850、1920×1080、最大化 | 要求した寸法で実際に表示できたことも記録する |
| DPI | 100%、150%、200% | 同じ論理寸法で、輪郭・文字・接地点・操作範囲を確認する |

歩行時間、攻撃時間、大型敵の倍率、カメラの追従方法の細部は、比較用の短い試作で確定する。入力を受け付ける頻度やゲーム速度を演出時間へ合わせて変更することは、これらの調整に含めない。

上表の応答時間・表示待ち上限も提案値であり、今回の調査で達成を確認した値ではない。実装時には測定機材と対象場面を固定し、数値の合否は実装担当が判定する。輪郭・存在感・動きの読みやすさは、その数値判定とは別にレモンが比較資料で判断する。

### 各フェーズに共通する確認版の条件

- 資料や画像だけでフェーズ完了とせず、英語・日本語のゲーム本体、ランチャー、Qt DLL、素材、データが揃った起動可能な確認版を用意する。通常のゲーム画面で操作を継続できることを必須とする。
- 確認版の配置先は `artifacts/rendering-phase-<番号>/<ビルド識別子>/` とし、前フェーズの確認版を残す。手直し後は新しい識別子へ出力し、起動中の確認版や通常の `dist` を上書きしない。
- 手動操作用に確認版専用の保存先・設定先を用意する。前フェーズと同じ検証用セーブのコピーで比較する作業は、R5/0-3の停止済み原本と作業コピーの条件に従う。0-1では通常の保存先を使わず、同じ確認版で新規開始・保存・終了・再開まで操作できることを確認する。
- 現行の `verify-runtime.ps1` は別コピーと専用設定で自動検証できるが、その実行は自動で終了する。継続プレイには0-1で追加した [start-manual-play.ps1](../scripts/start-manual-play.ps1) を使う。2026-10-28に英日で通常操作・保存・再開と保存先/設定先の分離を確認した（[結果と残件](phase0-manual-verification.md)）。フェーズ0全体の基準版完成とは区別する。
- 各フェーズでビルドと既存の起動・移動・Space・保存再開の自動検証を通し、そのフェーズに対応する操作手順でも確認する。自動検証の成功と、通常起動・手動操作の確認結果は分けて記録する。
- 確認の案内には、起動用スクリプトまたはショートカットの絶対パス、言語、確認用データの場所、操作手順、期待する表示、前フェーズとの差、既知の残件を記載する。
- 手動で再現しにくい敵・地形・特殊状態には、検証用セーブまたは再現手順を用意する。通常のゲーム画面で確認し、素材の一覧画像だけで代替しない。再現用の状態は通常セーブへ持ち込まない。
- 結果は「確認済み」「不合格」「未確認」に分け、実行ファイル・素材のハッシュ、画像・動画、ログと対応付ける。確認用ビルドが起動できない、基本操作が壊れている、当該フェーズの必須条件が不合格の場合は、そのフェーズを完了扱いにしない。
- フェーズ0〜6の区切りごとにClaude Codeへ読み取り専用レビューを依頼する。フェーズ5の5-1〜5-4でも同じ手順を行う。対象の差分、仕様、画像・動画、自動検証と手動確認の結果、既知の残件を提示する。
- レビューでは要求漏れ、画像制作の担当と新規制作の証跡、配置、ルール不変、視界・未鑑定情報の保護、確認版の再現性を点検する。指摘ごとに修正・非該当の根拠・未対応を記録し、重大な未解決事項がある間はそのフェーズを完了扱いにしない。修正後は該当項目の再確認とClaude Codeの再レビューを行う。
- レビュー結果はビルド識別子と対応付けて保存する。Claude Codeのソース上の確認と、実際のゲーム操作・画像の目視確認を混同しない。

ビルドと自動検証には、既存スクリプトの `OutputRoot`／`ApplicationRoot` を使う。以下は実装時に使う手順例であり、今回実行した結果ではない。

.\scripts\build-release.ps1 -Language all -OutputRoot $phaseRoot

手動操作には、0-1で追加した専用の起動手順を使う（[手順と制限](phase0-manual-play.md)）。自動検証用の `DARKDUNGEON_SMOKE_OUTPUT` は、継続プレイの手動確認には使わない。
