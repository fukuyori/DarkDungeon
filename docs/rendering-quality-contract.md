# R4 全素材の品質基準と制作工程の完了条件

作成日: 2026-10-28。状態: R4の仕様確定済み。[Claude Code再レビュー](../artifacts/claude-r4-quality-followup-20261028.txt)でhigh/mediumの未解決事項はなく、仕様を完了にできると判定された。R4の完了は基準・適用範囲・工程の整合性の確定を指す。画像やゲーム表示が合格したという意味ではない。

[表示品質仕様](rendering-parity-spec.md)のV-01〜V-08とA-01〜A-11を、[R3制作台帳](rendering-scope-inventory.md)の全対象に適用する。[R1](rendering-asset-contract.md)の形式・配置と[R2](item-appearance-contract.md)の外見保護は変更しない。原画はAntigravityへ依頼し、各フェーズ・5-1〜5-4の区切りでClaude Codeレビューを行う。

## 1. 全件に適用する範囲

[品質適用表](data/rendering-quality-plan.json)に、新規・派生2,165件と地形の監査122件、計2,287件を全件登録した。[集計](data/rendering-quality-summary.json)と[抽出・検査ツール](../tools/rendering-quality/README.md)で、R3との欠落・重複・古さを検出する。この表は内部監査専用で、CLIのプレイ観測やAntigravityへ丸ごと渡さない。

代表素材だけの合格を全素材へ流用しない。原画像、合成された主人公、性別表示、同じ外見の別名、各表示先の該当項目をすべて検証する。共通画像を使う場合も、共通元の合格と全別名・表示経路の接続を確認する。全種をクラス別画像の着色だけで済ませない。

品質適用表は検査の定義で、進捗や判定結果の正本ではない。進捗はR3台帳のtrackingと、そのquality_evidenceが参照する結果へ記録する。定義表の再生成で合格を推定したり、検査結果を初期化したりしない。現在の画像は全件未依頼・未納品・未組み込み・未検証。

適用表のprofilesは各Qを必須か非該当のいずれかに分類し、非該当には理由を持つ。例えば静的な像には歩行を要求せず、地形には新規PNGを要求しない。ただし透過・縮尺・表示先の検証は免除しない。ゲーム中に再現できないことだけで非該当とせず、R5のソース根拠・到達条件とClaudeレビューで確認する。理由が未確定なら未確認にする。

非該当理由は分類とQの組ごとに定義する。必須Qそのものを個別に免除せず、到達しない動作の枝にはケース単位の非該当と根拠を記録する。Qの合格は適用ケースがすべて合格し、未確認が残らないことを要求する。必須Q全体を変更するなら適用表の変更と再レビューを行う。

ビルド全体のA-09〜A-11（言語・画面・入力、ルール不変、遅延）は各工程の共通ゲート。FPSや操作結果を個々のPNGの検査だけで合格にしない。時間・縮尺等の初期案は表示品質仕様第6節に従い、達成済みとは扱わない。

## 3. 種類別の判定と制作前の確定事項

### 3.1 主人公とキャラクター

主人公42部位の原画検査に加え、描画対応390組を合成して4方向・徒歩・騎乗・行動・接地点・マントの着色を検査する。開始時73組と、プレイ中に到達できる組の通常画面での確認はR5の集合で分ける。存在しないゲーム状態を作るためにルールを変えない。描画対応表の合成検査は、通常プレイでその状態に到達した証拠ではない。

敵・仲間・NPCは766表示を同じ基準で扱う。新しい共通部位を使うことは許すが、色替えだけで種別の輪郭・動作を済ませない。性差がない場合の共通画像も両キーを明示して検査する。NOGEN、死体を残さない種、選択画面だけの種も素材対応から除外しない。

静的な攻撃方法をcontact/weapon/spell/ranged/engulf/proximity-effect/passive/death-effectに分類した。これは検査シナリオの候補で、プレイ中の攻撃通知を生成したり隠れた真の形を選ぶ表ではない。空の攻撃枠は行動として扱わず、受動ダメージ・死亡時爆発に自発的な武器攻撃を要求しない。幻覚などで表示された形の攻撃方法と実際の行動が異なる場合は、その新しい形で読める汎用の行動姿勢を使い、実体の姿へ戻さない。コアの攻撃結果や効果・経路を追加しない。

この静的分類はゲーム中の攻撃・行動の全集合ではない。getmattkは飲み込み・抱きつき等を一時的な爪/接触攻撃へ置き換え、SEDUCE設定でも攻撃を差し替える。AT_WEAPとAT_MAGCは距離で近接/遠隔に分かれ、杖・薬等の使用は静的な攻撃表の外で起こる。これらの分岐・置き換え・品物使用をR5のシナリオ一覧とR6の実際の行動通知の一覧へ渡す。依頼する姿勢を静的表だけで打ち切らず、実際に選ばれた通知を、公開された表示形で表す。

各素材は制作依頼前に、向きの有無、動きの形式、必要な動作、コマと接地点・座点、方向別合成順を宣言する。人型、四足、伸縮、蛇行、羽ばたき、浮遊などの宣言は描画の分類であり、ゲーム上の移動能力や速度を変えない。基準4列から増やす場合も48画素格子・4行と部位間の宣言を一致させる。全キャラクターに待機・移動時の姿・通知された行動の汎用姿を用意し、固有の攻撃方法に必要な追加姿勢は宣言して検証する。

### 3.2 騎乗

コアのcan_rideにある形の必要条件（humanoid、verysmallでない、bigmonstでない）を、英日それぞれ383種のコンパイル済み静的表に適用した。143種・両表示性別286件が候補、240種・480件が形の条件で対象外だった。英日の結果は一致した。候補は実際に変身・騎乗可能という判定ではない。変身禁止、到達手段、友好性、can_saddle、水中等はR5で確認し、必要な乗り手姿勢だけを依頼する。

乗り始めはmount_steedの別判定があり、変身中のslithyも拒否する。Hallucinationはforce以外で拒否され、Wounded_legsも通常は阻止する。forceでも残る判定や治療の分岐を通常条件と混同しない。騎乗後に変身した場合の継続はpolyselfからcan_rideを呼び、そこにはslithyの判定がない。この2経路をR5で別に確認する。例えばSALAMANDERは形の必要条件とpolyokを満たすslithy候補なので、先に乗ってから変身する経路を確認する。143候補のうちpolyokが真なのは64種だが、これは通常の変身制限の参考情報であり、元の主人公の形や特殊経路まで除外する根拠にしない。

一方、乗騎の表示が幻覚で変わる場合に備え、全766表示に乗騎としての座点・向き別の重なり方を用意する。これも全766種が実際の乗騎になれるという主張ではない。自分が擬態中なら擬態先、変身中なら許可された変身先を重ね、隠れた身体を出さない。品物・家具への擬態を重ねる場合は、当該新素材または保持地形と表示枠の接合規則を5-4で検査し、そのためだけの人間画像へ戻さない。

### 3.3 品物・像・特殊表示・UI

品物438外見は、48×48原画、背景の透過、明暗床での判読、持ち物等の実寸、R2のI-01〜I-13の該当項目を全件検証する。481定義との別名・汎用表示・外見だけの項目を落とさない。真の種類・中身・効果ごとの絵を追加して同じ外見を分裂させない。

像766は対応する新キャラクターの宣言した静止方向・コマから作り、親ハッシュと石化処理を記録する。生きた種の攻撃・歩行を像へ要求しない。幻覚の像がキャラクターglyphならキャラクターの基準を使う。死体は汎用外見1つに統合し、種別の別絵を作らない。

特殊表示120は、ビームの4方向、飲み込まれ8位置、爆発7種類×9位置、警告6段階、不可視・その他効果を、R3の同じ共有関係で検査する。位置関係・発生順・終了後の消去を確認し、効果が中心の主人公や周囲の輪郭を隠し続けない。品物の投擲にはコアの表示経路を使い、終点から通過経路を捏造しない。

UIの状態29・印3・起動1は、原画の形式だけでなく実寸、透過、状態とラベル、英日とDPIの組み合わせを確認する。空の状態画像1つ、墓石UI、47予約枠、3空領域、地形122件はauxiliary_gatesにも登録した。保持する背景をキャラクターの作り直し済み件数に含めない。

### 3.4 画風と数値の基準を固定する時点

旧保存ソースの地形36/キャラクター54の比率、向き別合成、保存画像の存在感を参照する。原画を複製しない。旧画像とソースが同一ビルドと確認できていないこと、旧動画がなく動作を実測比較できないことは比較資料に明記する。

フェーズ2では保持する明暗の床・壁・地形の実表示上に、新しい主人公・人型・四足・スライム・大型の試作を置き、見下ろし角、光、輪郭、色の範囲、身体の見かけの寸法、地面・座点と重なり順をstyle-guideへ記録し、レモンの目視確認を受ける。代表品物・小さいUI記号の判読基準も添える。フェーズ3・4で歩行・攻撃・待機・カメラと遅延の採用値を記録する。5へ入る前にこれらを版とハッシュ付きで固定する。

地形122件のQ03は、新しい素材が保持地形に調和するかを全件確認するもので、既存地形を自動で合格とするものでも、地形PNGを新規発注する条件でもない。まず新しい素材・画風見本を調整する。保持地形自体の変更が必要ならR1/R3への変更要求を作り、対象キー・画素保持条件・影響と再検証を先に確定し、再レビューする。確定するまで不合格を残し、元BMPの保持領域を勝手に塗り替えない。既存の描画不具合はコードの修正と回帰検証として扱う。

本R4は判定方法と確定時期を定める。未制作の絵の明暗・姿勢の具体値を、承認済み・実測済みとはしない。基準を変更する場合は変更理由・影響キーを記録して再レビューし、関連する素材を再検証する。大量制作を先行してから基準を後付けしない。

比較条件の役割と組み合わせは[R7](rendering-comparison-contract.md)で具体化する。phase0/1の現環境での最小記録と、phase5のA-09共通ゲート/phase6回帰に必要な英日×4窓条件×3拡大率の24行を区別する。物理環境で実行できない行は未確認として残し、代表場面や縮小画像で合格へ置き換えない。代表による動作校正も全対象の該当Qを免除しない。

各確認版はartifacts/rendering-phase-5-<工程>/<ビルドID>/へ新規出力し、英日ゲーム本体・ランチャー・Qt・素材・隔離した設定と保存先・起動手順を揃える。通常distや起動中の版を上書きしない。既存のbuild-release.ps1のOutputRoot等を使うが、この文書の作成では確認版を作っていない。

## 5. 全件の証拠と非該当の扱い

各キー・該当Qについて、判定はpass/fail/not-run/not-applicableとし、必要な証拠を持つ。空欄・未確認をpassにしない。not-applicableには適用表の理由、またはソースと到達条件の根拠、判断者、レビュー記録を添える。R5で再現できない候補は未確認のまま残し、形だけの抽出を根拠に到達済みとしない。

原画の全コマ・全方向、390合成、全別名・全glyphの解決は静的な全件検査を行う。合法な通常プレイの動作はR5のシナリオで実画面から確認する。描画専用の検査でのみ扱える組み合わせはrenderer-supportと区別し、通常プレイの到達・ルール不変・視界保護の成功へ流用しない。到達不能の動作を非該当にしても、新画像・全表示入力への対応・合成検査は免除しない。

結果に最低限、キー、Q、判定、原画/manifest/style-guideの版とSHA-256、親素材・処理版、実行ファイルとビルドID、言語、画面/迷宮の論理・実画素寸法、DPI/ズーム、再現ケース、期待値・実結果、画像/動画/ログ、判断者を記録する。品物の真の種類・生のglyph等が必要な検査用正解は内部資料へ分ける。通常の画像監査には外見グループだけを出す。

Q02等の数値は自動検査、Q03の存在感・輪郭とQ07/Q08の読みやすさは全素材の比較資料と動作で人が判断する。全コマの一覧画像だけでゲームでの欠け・入力遅延を合格にしない。生の差分画素やファイルハッシュの変化だけで新規性や動作の質を証明しない。

レモンの承認は画風見本と各工程の品質・比較結果に記録する。ロクは全件の検査・証拠・非該当の整合性を確認し、Claude Codeのソースレビューと実操作・目視判定を区別する。変更していない素材の原画承認を再利用する場合もハッシュと基準版を照合し、新しい確認版の実行時接続・回帰検証を省略しない。
