# R3 表示対象と画像制作の全件照合

再抽出日: 2026-10-28。状態: R3の制作範囲仕様は確定済み。[Claude Code最終確認](../artifacts/claude-r3-scope-final-20261028.txt)で、完了を妨げるhigh/mediumの残件はないと判定された。画像制作・ゲーム実装・画面確認の完了を意味しない。

R3は**制作範囲の確定**を扱う。画像制作、ゲームへの組み込み、画面品質の合格を意味しない。画像はAntigravityへ依頼し、各フェーズの区切りでClaude Codeへレビューを依頼する。[R1](rendering-asset-contract.md)の素材形式・全表示経路と[R2](item-appearance-contract.md)の外見保護を前提にする。

## 3. 主人公・キャラクター・像

主人公の未変身時は、コアが表示を許す職業・種族・性別・属性からR1の部位合成を行う。heroSheetの現在の40部位を新しい画像で置き換え、開始時に盾を持つナイト・僧侶の盾を追加し、合計42部位にする。2026-10-28にレモンが推奨案の採用を委任したことによる。その他の職業は「部位なし」と明記し、旧盾を補わない。現行の部位絵は実際の所持品全点を表現するものではない。装備欄の品物はコアの装備glyphとR2で扱う。

開始時に許可されない性別への変化もpolyself.c:change_sexにあるため、開始時73組だけを制作範囲としない。描画対応は390組を用意し、到達条件は検証用セーブ側で別管理する。属性は表示された属性種別を使い、三色のマントに接続する。三属性以外はR1の診断として扱い、隠された善悪値は使わない。変身時はコアのモンスターglyphに接続する。幻覚・飲み込まれ等では通常主人公を強制表示せず、コアが渡す状態を優先する。

383種×2表示性別の766件を、通常・仲間・検知・騎乗の各区間から同じ画像へ対応づけた。性差がない絵を納品する場合も、両方の論理キーから共通画像への別名を明示する。現在のクラス別画像の着色だけで全種作成済みとは扱わない。G_NOGENやG_NOCORPSEは除外理由にしない。選択・変身・特殊表示等から参照される範囲を保つ。リーダー・守護者・宿敵の役割対応も記録した。

職業選択の26件（13職業×2性別）は、新しい主人公の部位合成から静止画を作る。代表種族・属性は、その職業の開始時表の最初の許可組に固定し、表示性別だけを選択値に合わせる。具体値はhero.role_previews[].recipeに固定した。サムネイルと実行時で同じ合成定義・向き別順序・着色を使う。種族選択の10表示はhero.race_previewsの新しい種族キャラクター画像へ接続し、選択中の性別を使う。現在使われないQtの補助クラスの描画経路も監査から除かない。

像は766件を種別・表示性別ごとに登録し、新しいキャラクター画像から石化した静止画像を生成する。旧キャラクター画像からの生成は禁止する。死体はコアの全種の死体glyphを1つの汎用外見へ統合する。像の幻覚がキャラクターglyphになる場合は、持ち物・装備・メニューでもキャラクター表へ進む。

### 3.1 主人公の表示条件

MG_HEROは「主人公位置のモンスターglyph」に付くため、それだけで主人公合成を選ばない。コアのdisplay_selfが選んだ表示意味を、通知時点のスナップショットへ記録する。描画時にu.usteed等の実体から表示対象を補ったり、乱数を呼び直したりしない。未変身・擬態なしの本人表示であることと、コアが出したglyphがその時点のhero_glyphであることを照合してから、実際の職業・種族・性別・属性の合成を使う。

| 状態 | 表示する画像 |
|---|---|
| 通常の本人表示 | 実際の主人公の部位合成。職業選択用の代表合成に戻さない |
| showrace有効 | コアは種族glyphを選ぶが、本人表示の意味を保持し、実際の種族の身体を含む主人公合成を使う。NPC用の種族画像に置換しない |
| 騎乗・乗騎が表示された場合 | コアが選んだ乗騎の新素材に、その表示イベントで許可された本人の外見を上に重ねる。通常本人は実際の部位合成、変身なら自分の変身先、擬態なら擬態先とし、隠された素の身体を重ねない |
| 騎乗・乗騎が表示されない場合 | コアが出した本人表示だけを扱い、非表示の乗騎の姿を補わない |
| 品物・家具・モンスターへの擬態 | 擬態先としてコアが出した品物・地形・キャラクターの新素材。MG_HEROがあっても素の主人公を重ねない |
| 変身 | コアが出した変身先の新キャラクター画像。さらに擬態している場合は擬態先を優先 |
| 幻覚中の通常本人表示 | コアは通常の本人glyphを変えないので、実際の主人公合成を維持。他の対象や乗騎が幻覚glyphになった場合はその表示入力を使う |
| 飲み込まれ | swallowed()の周囲8位置は共通の新素材。中心のdisplay_selfの結果は上記と同じ規則で描き、普通の本人なら実際の主人公合成を使う。外の敵や地形を足さず、周囲8位置を描画枠で消さない |
| 透明・盲目・姿が見えない状態 | 状態フラグだけで本人を消したり復活させたりしない。コアが本人表示を出した場合だけ上記に従う。背景・不可視記号等だけを出した場合はそれだけを描く |

騎乗時の副表示は、display_selfのmaybe_display_usteedへ渡す「自分自身」の分岐と同じ、乱数を呼ばない表示選択から通知する。乗騎の抽選はコアが行った1回の結果だけを使い、副表示や描画で再抽選しない。幻覚で乗騎の見た目が変わった場合も、その表示された形の接合点と重なり順を使い、実際の乗騎種別を調べない。自分の形を描く許可は、そのコアの本人表示イベントに限定し、本人表示がないイベントで乗り手を復活させない。

全42部位は徒歩・騎乗の表示を制作範囲に含める。全766キャラクター表示は、幻覚で乗騎として表示される場合もあるので接合点・向き別の重なり順を持つ。一方、乗り手用の新しい姿勢・合成はコアが乗り手として許す形に限る。steed.c:can_rideは主人公の形がhumanoidで、verysmallでもbigmonstでもないことを要求し、乗騎の友好性や水中等も判定する。R4で形の候補と除外理由を整理し、R5で到達条件を照合してから依頼する。乗れない形すべてに乗り手用の別絵を発注しない。コマ・重なり方・再現手順と品質合格はR4・R5で定める。未対応のために旧画像や関係ない人間の姿へ戻さない。これらは素材定義の表示役割で、PNGを別に766枚発注するという意味ではない。

通常本人と、擬態・乗騎・変身先の判定には表示更新時の意味と世代を使う。主人公位置にあること、MG_HERO、変身していないことの組み合わせだけで推定しない。前の状態の合成やキャッシュを後描きで復活させない条件はR6へ接続する。種族選択のプレビューはコアが指定する種族・性別の新キャラクター画像とし、NPCと共通にする。マップ上の本人合成とは用途を分ける。

## 4. 品物の438外見への統合

画像キーのSHA-256入力はR2に従う。クラスキーはillobj/weapon/armor/ring/amulet/tool/food/potion/scroll/spellbook/wand/coin/gem/rock/ball/chain/venom。外見定義の種別文字列はdescription、明示登録した公開名はpublic-nameに固定する。NUL区切りの末尾にNULは付けず、英語原文の大文字小文字・空白を変えない。

本物と偽物の魔除け、灰色の石、袋、ランプ、角笛、同色の宝石などは同じ外見グループになる。元タイルが違っても同じ原画像・サムネイルを使う。実行時はコアが外見シャッフル等を処理して渡したタイルから、この静的な外見グループへ引く。実体のotypから絵を選び直すことは禁止する。宝石の色の変化もo_init.c:randomize_gem_colorsの結果を使い、元の宝石名に固定しない。

外見記述がない140件は、登録済みの英語公開名と静的な既知フラグが一致したときだけ受け入れる。CORPSEは汎用死体、EGGは種別・孵化状態を示さない卵、SLIME_MOLDは利用者設定の果物名を特定しない共通の果物、FIGURINEは隠された種別を示さない人形、通常品物glyphのSTATUEは汎用像とした。その他135件は登録済みの公開された形・名前だけを描く。初めから公開される名前と未鑑定の効果名を混同しない。新たなNULL外見を自動で真の名前へ置換しない。

17クラスの汎用表示では具体的な色・中身・材質を補わない。23件の外見だけの項目も制作対象に含む。積み重なり先頭は各外見・死体・像と同じ原画像への別名とし、印だけを重ねる。

## 7. 制作と完了の管理

論理的な新規・派生制作対象は2,165件。キャラクター766、像766、品物438、主人公部位42、特殊表示120、印3、状態アイコン29、起動・セーブ選択の画像1。職業キャラクター26件は主人公から合成し、像は新キャラクターから派生させる。別名・同一PNG・部位合成があるため、2,165枚を個別発注する意味ではない。地形122件は別途画風を監査する。

素材キーごとに制作方法、フェーズ、依頼・納品・組み込み・品質確認の状態、依頼記録、納品ハッシュ、組み込み証拠、品質確認証拠を持つ。新規対象は全件「未依頼・未納品・未組み込み・未検証」。件数の一致を画像完成とは扱わない。進捗が付いた定義・タイルへの接続を再生成で黙って変更・削除しない。主人公部位と旧画像一覧はrendering-scope-baseline.jsonの固定登録から取得し、新たな納品ファイルを旧画像へ追加しない。R4で受入条件を定め、フェーズ5-1〜5-4へ接続する。

R3の合格条件は、全項目・全glyph・全タイル・全主人公対応の分類、未鑑定品の共通外見、全表示経路、再生成検査、Claude Codeの指摘対応が揃うこと。ゲームの完成には各フェーズの実行可能版、実行時の情報保護、操作と画面の確認、レモンの目視確認が別途必要になる。
